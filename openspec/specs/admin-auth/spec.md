# admin-auth Specification

## Purpose
定义 BookHub 管理端的身份与权限契约：管理员登录、会话生命周期、admin 与 editor 角色边界、口令与账号管理、初始管理员引导，以及写操作的审计留痕与管理端表单的 CSRF 防护。

## Requirements

### Requirement: 管理员登录凭据校验

登录 MUST 使用「用户名 + 密码」两项凭据。凭据正确且账号处于启用状态时 MUST 建立管理端会话并进入管理界面。用户名不存在、密码错误、账号已禁用三种情况 MUST 返回同一种失败结果与同一条错误文案，MUST NOT 泄露账号是否存在，MUST NOT 回显所提交的密码。

「不泄露账号是否存在」MUST 包含**响应耗时**：用户不存在时 MUST 用一份固定的合法 bcrypt 哈希做一次真实校验，使两条分支的耗时处于同一量级。任何长度的密码（含超过 bcrypt 72 字节上限、空串）MUST 被安全处理：MUST NOT 抛未捕获异常，MUST NOT 让匿名请求得到 5xx。

#### Scenario: 用户不存在与密码错误得到相同失败结果

- **WHEN** 使用不存在的用户名提交登录表单
- **THEN** 返回与「密码错误」完全一致的失败文案与响应状态
- **AND** 响应中不含任何能判断该用户名是否存在的提示
- **AND** 响应耗时与「密码错误」处于同一量级（不是数量级差异）

#### Scenario: 凭据正确时建立会话

- **WHEN** 使用正确的用户名与密码提交登录表单
- **THEN** 建立管理端会话并进入管理界面
- **AND** 该账号最近一次成功登录时间被更新

#### Scenario: 超长密码不会打出 5xx

- **WHEN** 用不存在的用户名与超过 72 字节的密码提交登录
- **THEN** 返回 401 与普通失败文案
- **AND** 服务端不产生未处理异常

### Requirement: 登录失败频次限制

同一来源在时间窗口内连续登录失败达到阈值后，系统 MUST 停止校验凭据，并在窗口剩余时间内拒绝继续尝试，以「过多请求」语义（HTTP 429）响应并给出稍后重试的提示。窗口结束或被判定为新的窗口后 MUST 恢复允许尝试。被限流的请求 MUST NOT 触发凭据校验，也 MUST NOT 泄露账号是否存在。

限制 MUST 有两层：按「来源 IP + 用户名」的账号级计数，以及**按来源 IP 的总尝试数**。后者 MUST 让「不停更换用户名」的喷洒同样被限流（否则换一个用户名就重新获得额度）。用于计数的内存结构 MUST 有硬上限，不能因为来源或用户名无限增长。

#### Scenario: 达到失败阈值后继续尝试被限流

- **WHEN** 同一来源在窗口内连续失败达到阈值后再次提交登录
- **THEN** 返回 429 与稍后重试提示
- **AND** 本次提交未进行凭据校验

#### Scenario: 窗口结束后恢复可尝试

- **WHEN** 失败计数所在的时间窗口已结束
- **THEN** 该来源的登录请求不再被限流
- **AND** 正确凭据可正常建立会话

#### Scenario: 换用户名也不能绕过

- **WHEN** 同一来源在窗口内用不同用户名连续尝试登录，累计超过每 IP 上限
- **THEN** 后续尝试返回 429
- **AND** 不再对提交的凭据做校验

#### Scenario: 计数结构不随来源增长

- **WHEN** 限流器记录的 key 数量超过内部上限
- **THEN** 过期的桶被清掉，仍超限时最旧的桶被淘汰
- **AND** 内存占用不随请求量单调增长

### Requirement: 管理端会话有效期与登出

管理端会话 MUST 由带有效期且服务端可判定有效性态的 Cookie 承载，该 Cookie MUST 带 `HttpOnly` 与 `SameSite=Lax`，在要求 HTTPS 的部署配置下 MUST 追加 `Secure`。会话过期或失效后，访问任意管理端页面 MUST 重定向到登录页且 MUST NOT 渲染任何管理数据。登出 MUST 立即使当前会话失效，而不等待 Cookie 自然到期。

#### Scenario: 会话过期后访问管理端

- **WHEN** 会话超过有效期后请求任意管理端页面
- **THEN** 响应为重定向到登录页
- **AND** 响应中不含任何管理数据

#### Scenario: 登出后旧会话立即失效

- **WHEN** 已登录管理员执行登出
- **THEN** 当前会话立即失效
- **AND** 用登出前的 Cookie 再次请求管理端页面时被重定向到登录页

### Requirement: 角色权限边界

系统 MUST 区分 `admin` 与 `editor` 两种角色。`editor` MUST 能执行全部内容类操作（Book 与章节的创建、修改、排序、发布、软删除与恢复、版本查看与回滚），但 MUST NOT 新增或管理账号、MUST NOT 修改站点设置、MUST NOT 查看审计日志。对无权操作的请求 MUST 返回 403 且 MUST NOT 产生任何数据变更；管理界面 MUST NOT 向 `editor` 呈现其无权使用的入口。

#### Scenario: editor 访问账号、站点设置与审计被拒绝

- **WHEN** `editor` 请求新增账号、修改站点设置或查看审计日志
- **THEN** 返回 403
- **AND** 相关数据未发生任何变更

#### Scenario: editor 的管理界面不呈现受限入口

- **WHEN** `editor` 打开管理界面
- **THEN** 界面中不出现账号管理、站点设置与审计日志的入口
- **AND** 内容类操作的入口正常可用

### Requirement: 密码策略与修改校验

密码 MUST 只以单向哈希形式保存，明文 MUST NOT 持久化、MUST NOT 写入日志或审计记录，任何界面与接口 MUST NOT 回显密码。超过长度上限（72 字节）的新密码 MUST 在保存前被拒绝并给出校验错误，MUST NOT 被静默截断。

#### Scenario: 超长密码被拒绝

- **WHEN** 提交超过 72 字节的新密码
- **THEN** 返回校验错误
- **AND** 该账号密码未发生变更

#### Scenario: 过短或与用户名相同的密码被拒绝

- **WHEN** 提交少于 10 个字符的新密码，或提交与用户名完全相同的密码
- **THEN** 返回校验错误并说明密码强度不足
- **AND** 该账号密码未发生变更

### Requirement: 凭据或账号状态变更导致会话立即失效

管理员密码被本人修改、被其他管理员重置，或账号被禁用后，该账号此前建立的全部会话 MUST 立即失效。后续携带旧会话的请求 MUST 按未登录处理（重定向到登录页或返回 401），MUST NOT 继续以旧权限执行操作。

#### Scenario: 密码被重置后旧会话失效

- **WHEN** 管理员 A 重置账号 B 的密码
- **THEN** 账号 B 的既有会话立即失效
- **AND** 账号 B 用旧会话访问管理端被重定向到登录页

#### Scenario: 账号被禁用后会话失效且无法重新登录

- **WHEN** 管理员禁用某账号
- **THEN** 该账号的既有会话立即失效
- **AND** 该账号即使提交正确密码也无法建立新会话

### Requirement: 初始管理员引导

服务启动时 MUST 依据初始管理员环境变量（`BOOKHUB_INITIAL_ADMIN_USER` 与 `BOOKHUB_INITIAL_ADMIN_PASSWORD`）幂等创建首个 `admin` 账号。该账号已存在时 MUST NOT 修改其密码、角色或启用状态，MUST NOT 产生重复账号。变量值缺失或为空时 MUST NOT 创建或修改任何账号。

#### Scenario: 首次启动创建初始管理员

- **WHEN** 数据中不存在初始管理员账号且两个变量均已提供
- **THEN** 创建一个 `admin` 角色账号
- **AND** 可用该用户名与密码登录

#### Scenario: 已存在时不覆盖密码

- **WHEN** 初始管理员账号已存在且变量中的密码与之不同
- **THEN** 以原有密码仍可登录
- **AND** 不新增重复账号、账号角色与启用状态保持不变

### Requirement: 账号管理

`admin` MUST 能新增管理员账号（用户名、显示名、角色、初始密码）、启用或禁用账号、重置任意账号的密码。用户名为空或与现有账号重复时 MUST 被拒绝并返回校验错误。被禁用的账号 MUST 无法登录，重新启用后 MUST 恢复可登录。

#### Scenario: 重复用户名被拒绝

- **WHEN** 新增账号时提交已存在的用户名
- **THEN** 返回校验错误
- **AND** 不创建新账号

#### Scenario: 禁用后不能登录、重新启用后恢复

- **WHEN** 某账号被禁用后提交正确凭据登录
- **THEN** 登录被拒绝并按未授权处理
- **AND** 该账号被重新启用后可用正确凭据登录

### Requirement: 写操作审计记录

每一次成功的写操作（Book、章节内容、版本回滚、账号、站点设置）MUST 追加一条审计记录，包含操作者、动作、对象类型、对象标识与可读标签、操作时间（UTC）、来源 IP；内容类操作还 MUST 记录变更前后的版本号。审计记录 MUST NOT 通过管理界面被修改或删除。写操作失败时 MUST NOT 产生审计记录。

#### Scenario: 替换章节内容记录前后版本号

- **WHEN** 管理员替换某个章节的正文并保存成功
- **THEN** 追加一条审计记录
- **AND** 该记录含操作者、动作、对象标识、时间、来源 IP 与变更前后的版本号

#### Scenario: 失败的写操作不留审计记录

- **WHEN** 一次写操作因校验失败被拒绝
- **THEN** 不追加审计记录

### Requirement: 审计记录查询与筛选

`admin` MUST 能按 Book 与章节筛选审计记录，并按时间倒序分页查看。每条结果 MUST 展示操作者、动作、对象、时间与来源 IP。筛选条件无匹配时 MUST 返回空结果集合，而 MUST NOT 返回错误。

#### Scenario: 按 Book 与章节筛选

- **WHEN** `admin` 以某 Book 及其下某章节为条件查询审计记录
- **THEN** 只返回与该 Book 及其章节相关的记录
- **AND** 结果按时间倒序排列

#### Scenario: 无匹配时返回空结果

- **WHEN** 筛选条件不匹配任何审计记录
- **THEN** 返回空结果集合
- **AND** 响应状态不表示错误

### Requirement: 管理端表单 CSRF 防护

所有改变状态的管理端表单提交 MUST 携带与当前会话绑定的 CSRF token。token 缺失、被篡改或不属于当前会话时 MUST 返回 403，且该请求 MUST NOT 产生任何数据变更，MUST NOT 回显 token 值。

#### Scenario: 缺少 token 的提交被拒绝

- **WHEN** 提交管理端表单时未携带 CSRF token
- **THEN** 返回 403
- **AND** 请求对应的数据未发生任何变更

#### Scenario: 其他会话签发的 token 被拒绝

- **WHEN** 提交管理端表单时携带的 token 来自另一个会话
- **THEN** 返回 403
- **AND** 请求对应的数据未发生任何变更

### Requirement: 程序化访问 MUST 通过 API Token 完成

除人类会话登录外，系统 MUST 支持以 API Token 作为身份来源。Token MUST 可命名、可设作用域（`read` / `write` / `admin`）、可选过期时间、可吊销；创建时 MUST 只显示一次明文，数据库 MUST 只保存不可逆哈希。系统 MUST 记录每个 Token 的最近使用时间与创建者。

#### Scenario: 创建后只显示一次

- **WHEN** 管理员在管理端创建一个 Token 并离开页面
- **THEN** 明文只在创建成功时显示，之后无法再次查看
- **AND** 列表中只显示名称、作用域、创建时间与最近使用时间

#### Scenario: 吊销后立即失效

- **WHEN** 管理员吊销某个 Token 后，客户端再用它调用接口
- **THEN** 请求被拒绝（401）
- **AND** 不影响其他 Token 与人类会话

#### Scenario: 过期 Token 不可用

- **WHEN** 使用已超过过期时间的 Token 调用接口
- **THEN** 返回 401 并说明凭据已过期
