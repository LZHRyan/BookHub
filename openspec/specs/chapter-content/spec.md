# chapter-content Specification

## Purpose
定义章节正文的内容契约：Markdown 与 HTML 双格式原文的保存与取回、上传编码归一化、正文大小限制、Markdown 渲染管线产出的可观测结果、HTML 白名单净化后的安全边界，以及渲染结果缓存对读者的可见行为。

## Requirements

### Requirement: 节正文双格式保存

每一个节 MUST 声明内容格式为 `markdown` 或 `html` 之一，且该格式 MUST 等于所属 Book 的文档类型（整本统一，不允许混排）。系统 SHALL 按上传或提交的原文原样保存正文，MUST NOT 在保存阶段改写语法结构；读取原文时 MUST 返回与保存时一致的内容（编码归一化除外）。格式仅决定展示与渲染路径，不影响原文的可取回性。

#### Scenario: Markdown 原文原样取回

- **WHEN** 管理员提交一份含表格与代码块的 Markdown 正文并保存
- **THEN** 按原文通道读取该节时，返回内容与提交内容逐字符一致
- **AND** 返回的格式标注为 `markdown`

#### Scenario: HTML 原文原样取回

- **WHEN** 管理员提交一份 HTML 正文并保存
- **THEN** 按原文通道读取该节时，返回内容与提交内容逐字符一致
- **AND** 返回的格式标注为 `html`

#### Scenario: 未指定格式时拒绝保存

- **WHEN** 提交的节声明的格式不属于 `markdown`、`html`
- **THEN** 系统拒绝保存并返回 4xx 状态码
- **AND** 错误信息指明格式取值非法

#### Scenario: 未指定格式时继承 Book 默认值

- **WHEN** 提交节时完全未声明格式
- **THEN** 系统按所属 Book 的文档类型保存该节
- **AND** 保存后的格式标注等于该 Book 的文档类型

#### Scenario: 格式与 Book 不一致时拒绝

- **WHEN** 向一本 Markdown 的 Book 提交声明为 `html` 的节
- **THEN** 系统拒绝保存并提示这本书是 Markdown 类型
- **AND** 该 Book 下不会出现 HTML 节

### Requirement: 正文长度与上传大小限制

系统 MUST 对单个节的正文长度与上传文件大小施加明确上限。超过上限时系统 SHALL 拒绝保存并返回可辨识的错误（正文超长与文件过大使用不同错误标识），且 MUST NOT 写入被截断的内容、MUST NOT 产生新的历史版本。

#### Scenario: 正文超长被拒绝

- **WHEN** 提交的正文长度超过允许上限
- **THEN** 系统返回 4xx 状态码并标明为正文超长
- **AND** 该节内容与版本号保持提交前的状态

#### Scenario: 上传文件过大被拒绝

- **WHEN** 通过上传文件新增节且文件大小超过允许上限
- **THEN** 系统返回 4xx 状态码并标明为文件过大
- **AND** 不创建节、不产生版本记录

#### Scenario: 恰好等于上限时接受

- **WHEN** 提交的正文长度等于允许上限
- **THEN** 系统正常保存并返回成功

### Requirement: 上传编码归一化

系统 SHALL 在接收上传文件时自动识别编码，识别顺序 MUST 为：UTF-8（含 BOM）、严格 UTF-8、GB18030。识别成功后正文 MUST 以 UTF-8 保存且不带 BOM；三种输入编码下文本内容 MUST 完全等价。若按上述顺序都无法解码，系统 MUST 拒绝该文件并返回可读错误，不得保存乱码内容。

#### Scenario: UTF-8 与带 BOM 的 UTF-8 结果一致

- **WHEN** 分别上传同一份中文文档的无 BOM 版本与带 BOM 版本
- **THEN** 两次保存后的正文内容完全相同
- **AND** 保存结果中不包含 BOM 字符

#### Scenario: GB18030 文档被正确转换

- **WHEN** 上传一份 GB18030 编码的中文文档
- **THEN** 保存成功，正文内容与原文语义一致且无乱码字符
- **AND** 按原文通道取回的内容为合法 UTF-8

#### Scenario: 无法解码时拒绝保存

- **WHEN** 上传一份按上述顺序均无法解码的二进制或损坏文件
- **THEN** 系统返回 4xx 状态码并提示编码无法识别
- **AND** 不创建节、不产生版本记录

### Requirement: Markdown 扩展语法渲染

对于格式为 `markdown` 的节，系统 SHALL 渲染为结构化 HTML 并支持扩展语法：表格、删除线、任务列表、围栏代码块与脚注。渲染结果 MUST 以真正的结构化元素呈现（例如表格输出为表格元素、任务列表输出为带勾选状态的列表项），而不是纯文本。

#### Scenario: 表格渲染为表格结构

- **WHEN** 节正文包含一个 Markdown 表格
- **THEN** 渲染结果包含表格元素及对应的表头与单元格

#### Scenario: 任务列表保留勾选状态

- **WHEN** 节正文包含已完成与未完成两项任务列表
- **THEN** 渲染结果中两项分别呈现为已勾选与未勾选状态

#### Scenario: 围栏代码块保留语言信息

- **WHEN** 节正文包含一个标注了语言的围栏代码块
- **THEN** 渲染结果中该代码块保留原始文本与缩进
- **AND** 渲染结果标记了该代码块的语言

#### Scenario: 脚注生成可跳转的引用

- **WHEN** 节正文包含脚注引用与脚注定义
- **THEN** 渲染结果中正文处的引用可跳转至文末的脚注内容
- **AND** 脚注文本出现在渲染结果的末尾区域

### Requirement: 代码语法高亮

对于标注了语言的代码块，系统 SHALL 在渲染结果中按语言着色，且 MUST 对代码内容做转义处理，代码块内的标记文本 MUST NOT 被当作页面标记执行或改变页面结构，也不得破坏页面其余部分的排版。

#### Scenario: 代码块内的标记文本被转义

- **WHEN** 节正文的代码块中包含形如一整段标签的示例文本
- **THEN** 渲染结果显示该文本本身
- **AND** 页面其余结构不受影响，浏览器不会把该文本解析为页面元素

#### Scenario: 未知语言的代码块仍正常显示

- **WHEN** 代码块标注了一个系统不支持着色的语言名
- **THEN** 代码块仍以等宽方式正常显示，内容完整
- **AND** 请求不返回错误

### Requirement: 标题锚点与页内目录

系统 SHALL 为渲染结果中的每个标题生成稳定的锚点标识，并据同一份标题序列生成页内目录（TOC）。同一份内容重复渲染时，锚点 MUST 保持一致；标题文本重复时，锚点 MUST 各不相同以保证可唯一定位。

#### Scenario: 标题生成可跳转锚点

- **WHEN** 节正文包含多个不同级别的标题
- **THEN** 渲染结果中每个标题都带有锚点标识
- **AND** 通过锚点链接可直接定位到对应标题

#### Scenario: 重复标题的锚点不冲突

- **WHEN** 节正文中出现两个文本相同的标题
- **THEN** 两个标题的锚点互不相同
- **AND** 页内目录中两项分别指向各自位置

#### Scenario: 页内目录结构与标题层级一致

- **WHEN** 查看一个包含多级标题的节阅读页
- **THEN** 页内目录按标题出现顺序排列且体现层级关系
- **AND** 目录项数量与渲染结果中的标题数量一致

### Requirement: Markdown 内嵌标记不直接生效

对于格式为 `markdown` 的节，正文中直接出现的标记（标签形态的文本）MUST NOT 被当作结构解析，而 SHALL 以文本形式呈现。因此 Markdown 节的安全性 MUST 只取决于系统自身的渲染与净化规则，而不依赖作者是否写了危险标记。

#### Scenario: 内嵌标签被当作文本

- **WHEN** 一份 Markdown 节正文中出现一段直写的标签文本
- **THEN** 渲染结果中以文本形式显示该段内容
- **AND** 该标记不会在页面中生成任何可执行元素

### Requirement: HTML 白名单净化

对于格式为 `html` 的节，系统 MUST 在保存与展示两条路径上都按白名单净化：脚本类标签（`<script>`）、`<iframe>`、`<object>`、`<form>` 等元素 MUST 被整段移除，`on*` 事件属性 MUST 被删除，`javascript:` 等危险协议的链接 MUST 被剔除；标题、段落、列表、表格、代码、图片、链接、折叠区块等白名单元素 MUST 保留。净化 MUST NOT 改动白名单内的正文文本。

#### Scenario: 脚本标签被整段移除

- **WHEN** 一份 HTML 节包含 `<script>` 元素
- **THEN** 渲染结果与按原文通道保存的净化结果中都不含该元素
- **AND** 脚本内容不会在阅读页执行

#### Scenario: 内联事件属性被删除

- **WHEN** 一份 HTML 节的图片标签带有 `onerror` 形式的事件属性
- **THEN** 渲染结果中该元素保留但事件属性被移除
- **AND** 页面加载该节时不会触发该属性中的内容

#### Scenario: 危险协议链接被剔除

- **WHEN** 一份 HTML 节包含以 `javascript:` 开头的链接
- **THEN** 输出中的链接不再带有该协议地址

#### Scenario: 结构性容器被移除

- **WHEN** 一份 HTML 节包含 `<iframe>` 与 `<form>` 元素
- **THEN** 输出中不出现这些元素
- **AND** 其中的白名单正文文本仍按净化规则保留

#### Scenario: 白名单内容不被改写

- **WHEN** 一份 HTML 节只包含标题、段落、列表、表格与代码块
- **THEN** 净化后这些元素与其文本内容全部保留

### Requirement: 渲染结果缓存与失效

系统 SHALL 缓存节的渲染结果以保障阅读性能，且缓存 MUST 以内容为失效依据：节正文一旦发生变化，读者下一次请求 MUST 看到新内容对应的渲染结果，不得返回旧缓存。正文未变化时，重复请求得到的渲染结果 MUST 完全一致。

#### Scenario: 内容变更后立即可见

- **WHEN** 管理员替换了某节的正文，随后读者立即访问该节
- **THEN** 页面显示新内容对应的渲染结果
- **AND** 不出现旧标题、旧段落或旧表格

#### Scenario: 未变更时渲染结果稳定

- **WHEN** 对同一份未变更的节连续请求两次
- **THEN** 两次得到的渲染结果完全相同

#### Scenario: 格式切换后按新格式渲染

- **WHEN** 管理员把某节的格式由 `html` 改为 `markdown` 并保存新的正文
- **THEN** 读者看到的是按 Markdown 规则渲染的结果
- **AND** 不再出现按 HTML 规则处理的旧结果

### Requirement: 正文中的站内媒体引用 MUST 按部署前缀解析

节正文里的站内媒体地址 MUST 以 `/media/` 开头的根相对路径表达，渲染输出时 MUST 按部署前缀（`ROOT_PATH`）补全为可访问地址；未配置前缀时 MUST 原样保留。净化流程 MUST 保留站内媒体引用，MUST NOT 因为 `src` 指向自身而丢弃标签。

#### Scenario: 根路径部署原样保留

- **WHEN** 未配置部署前缀，正文含 `![图](/media/demo/ab12-arch.png)`
- **THEN** 渲染结果中该图片的 `src` 仍为 `/media/demo/ab12-arch.png`

#### Scenario: 子路径部署自动补前缀

- **WHEN** 部署前缀为 `/kb`，同一正文被渲染
- **THEN** 渲染结果中该图片的 `src` 为 `/kb/media/demo/ab12-arch.png`

#### Scenario: 净化不丢弃站内图片

- **WHEN** 一份含站内媒体引用的 Markdown 正文经过白名单净化
- **THEN** `<img>` 标签与 `src`、`alt` 属性均被保留
- **AND** 渲染后的页面请求该地址返回 200
