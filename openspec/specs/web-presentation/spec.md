# web-presentation Specification

## Purpose
定义 BookHub 的界面表现契约：统一的设计令牌与组件、明暗主题与首屏无闪烁、站点标识、阅读页排版、导航与响应式、管理端信息层次、可访问性基线、空态与错误页，以及动效克制。

## Requirements

### Requirement: 界面 MUST 由统一的设计令牌派生

所有页面 MUST 使用同一套语义化设计令牌（背景、表面、边框、文字层级、强调色、语义色、圆角、阴影、间距、字体）渲染。组件样式 MUST 只引用令牌而不写死具体色值；修改强调色时 MUST 只改令牌定义即可全站生效。

#### Scenario: 修改强调色后全站一致

- **WHEN** 把强调色令牌从默认值改为另一种颜色
- **THEN** 顶部导航、主按钮、链接、焦点环与选中态同时变为新颜色
- **AND** 不需要修改任何页面模板

#### Scenario: 亮暗两套令牌覆盖同一批组件

- **WHEN** 在亮色与暗色主题下分别打开首页、阅读页与管理端列表
- **THEN** 三个界面的组件形状、间距与层级保持一致
- **AND** 仅颜色取值不同

### Requirement: 主题 MUST 支持跟随系统、亮色、暗色三态

界面 MUST 提供「跟随系统 / 亮色 / 暗色」三态切换，选择结果 MUST 在刷新与后续访问中保持。首屏渲染 MUST NOT 出现亮暗闪烁；当浏览器禁用脚本时，界面 MUST 退化为跟随系统偏好。

#### Scenario: 选择暗色后刷新保持

- **WHEN** 用户切换到暗色主题并刷新页面
- **THEN** 页面在首次绘制时即为暗色，不出现先亮后暗的闪烁
- **AND** 再次访问站点仍为暗色

#### Scenario: 跟随系统时随系统变化

- **WHEN** 用户选择「跟随系统」，随后把操作系统切换到暗色外观
- **THEN** 页面在不手动操作的情况下呈现暗色

#### Scenario: 禁用脚本仍可用

- **WHEN** 浏览器禁用 JavaScript 且系统为暗色外观
- **THEN** 页面以暗色呈现，内容与操作均可正常使用

### Requirement: 站点标识 MUST 在浏览器中可见

站点 MUST 提供图标资源，浏览器标签页 MUST 显示该图标而不再请求到 404。页面标题 MUST 采用「页面名 · 站点名」格式，站点名为空时 MUST 只显示页面名。随主题切换，浏览器地址栏强调色 MUST 与当前主题匹配。

#### Scenario: 标签页有图标

- **WHEN** 打开任意页面并查看浏览器标签页
- **THEN** 标签页显示站点图标
- **AND** 站点不再返回图标资源不存在的错误

#### Scenario: 标题格式统一

- **WHEN** 打开章节阅读页
- **THEN** 浏览器标题为「章节标题 - Book 标题 · 站点名」形式的组合
- **AND** 首页标题只包含站点名

### Requirement: 阅读页 MUST 保证长文可读性

章节正文 MUST 以受限行宽呈现（约 60–80 个字符），行高 MUST 不低于 1.6。标题 MUST 呈现至少 4 级明显的层级差异。代码块与表格在超宽时 MUST 横向滚动且 MUST NOT 撑破页面布局；打印时 MUST 隐藏导航、侧栏与分页控件，正文满宽输出。

#### Scenario: 超宽表格不破坏布局

- **WHEN** 章节正文包含列数很多、宽度超过容器的表格
- **THEN** 表格在自身区域内横向滚动
- **AND** 页面整体不出现横向滚动条

#### Scenario: 打印为可读文档

- **WHEN** 浏览器打印某个章节
- **THEN** 输出中不包含顶部导航、页内目录侧栏与上下篇控件
- **AND** 正文按页面宽度排版

### Requirement: 导航 MUST 标明当前所在位置

顶部导航与侧栏 MUST 用视觉与语义标记当前所在区域（`aria-current`），面包屑 MUST 反映「站点 / Book / 章节」层级。图标按钮 MUST 具备可读名称，不留无语义的纯图标按钮。

#### Scenario: 当前导航被标记

- **WHEN** 管理员停留在「账号管理」页面
- **THEN** 侧栏对应项处于选中态，并带有 `aria-current` 标记
- **AND** 其他项为普通态

#### Scenario: 图标按钮有名称

- **WHEN** 使用屏幕阅读器浏览顶栏的主题切换按钮
- **THEN** 该按钮读出明确的名称（如「切换主题」）
- **AND** 不读出「按钮」而无文字

### Requirement: 布局 MUST 在小屏下可用

视口宽度小于 960px 时，管理端侧栏 MUST 变为可横向滚动的导航条，正文与表格 MUST NOT 产生整页横向滚动。视口宽度小于 720px 时，顶栏搜索框 MUST 收起为可展开的入口。所有可点击控件的触控区域 MUST 不小于 40×40 像素。

#### Scenario: 手机宽度下仍可操作

- **WHEN** 在 390px 宽视口打开管理端 Book 详情
- **THEN** 章节表格在自身容器内横向滚动
- **AND** 导航入口与操作按钮仍可点击且不被裁切

#### Scenario: 搜索框折叠

- **WHEN** 在 390px 宽视口打开首页
- **THEN** 顶栏以图标入口呈现搜索
- **AND** 点击后展开输入框并可提交搜索

### Requirement: 管理端 MUST 区分操作权重与信息层次

管理端列表 MUST 让标题、次要信息与操作区形成清晰的视觉层次；破坏性操作 MUST 与普通操作在视觉上可区分（不同颜色/位置），且 MUST 二次确认。表单 MUST 在字段级展示错误提示与帮助文本。

#### Scenario: 删除操作不与编辑混淆

- **WHEN** 查看 Book 列表的某一行操作区
- **THEN** 删除类操作使用危险语义的视觉样式
- **AND** 点击后要求确认才执行

#### Scenario: 字段错误就近提示

- **WHEN** 提交 Book 表单时标题为空
- **THEN** 标题输入框旁出现错误提示且输入框呈现错误态
- **AND** 其他字段仍保留用户已填内容

### Requirement: 列表与错误 MUST 有明确空态与统一错误页

每个列表页在没有数据时 MUST 展示说明性空态（说明为什么空、下一步做什么），MUST NOT 只留空白。404、403、500 等错误 MUST 使用统一的错误页面，包含状态码、可读说明与返回入口。

#### Scenario: 空 Book 列表

- **WHEN** 站点还没有任何公开 Book
- **THEN** 首页显示「还没有内容」的空态说明
- **AND** 说明中包含管理员如何开始的提示

#### Scenario: 访问不存在页面

- **WHEN** 访问一个不存在的章节地址
- **THEN** 返回统一错误页并显示 404
- **AND** 页面提供返回首页入口

### Requirement: 界面 MUST 满足可访问性基线

所有表单控件 MUST 与可见标签关联。键盘聚焦 MUST 有清晰可见的焦点指示，MUST NOT 依赖颜色单独表达状态。正文文字与背景的对比度 MUST 达到 WCAG AA（≥4.5:1）。当系统要求减少动效时，界面 MUST 关闭过渡与动画。

#### Scenario: 键盘浏览可见焦点

- **WHEN** 使用 Tab 键在登录表单中移动焦点
- **THEN** 当前焦点元素有清晰的轮廓指示
- **AND** 焦点顺序与视觉顺序一致

#### Scenario: 减少动效

- **WHEN** 用户的系统设置为减少动态效果
- **THEN** 页面切换与悬停不再播放入场/位移动画
- **AND** 功能保持完整

### Requirement: 首页卡片 MUST 支持封面布局并回退图标

首页 Book 卡片在有封面时 MUST 以固定高度展示封面图（`object-fit: cover`，等比例裁切），无封面时 MUST 回退为 emoji 图标块；两种状态 MUST 保持卡片高度与文字基线一致，标题与摘要 MUST 限制行数并截断，MUST NOT 因为摘要过长而撑破卡片。

#### Scenario: 有封面与无封面卡片对齐

- **WHEN** 首页同时渲染一本有封面与一本无封面的 Book
- **THEN** 两张卡片高度一致
- **AND** 有封面的显示图片，无封面的显示图标块

#### Scenario: 摘要过长不撑破卡片

- **WHEN** 某 Book 的摘要超过三行
- **THEN** 摘要被截断为固定行数并保留省略号
- **AND** 卡片内的章节数与更新时间仍可见

### Requirement: Book 详情 hero MUST 在有封面时展示缩略图

Book 详情页 hero 区在有封面时 MUST 展示封面缩略图（固定宽高、圆角、比例裁切），无封面时只有图标与标题；小屏下封面 MUST 缩为图标尺寸或隐藏，MUST NOT 挤压标题造成换行错乱。

#### Scenario: 详情页显示封面

- **WHEN** 打开一本已设置封面的 Book
- **THEN** hero 区出现封面缩略图
- **AND** 标题、摘要与元信息仍完整可见

### Requirement: 首页 MUST 按组分区渲染

首页 MUST 以组为单位分区展示 Book：每个分区有一个组标题（可带图标与简介）与其下的 Book 卡片网格，分区之间 MUST 有可见的分隔。MUST NOT 把所有组的 Book 混排成一个网格。

#### Scenario: 两个组各自成区

- **WHEN** 首页存在「基础设施」与「规范制度」两个组且都有公开 Book
- **THEN** 页面出现两个分区，各自有组标题
- **AND** 每个分区只包含该组的 Book

#### Scenario: 组标题可点击筛选

- **WHEN** 读者点击某分区标题
- **THEN** 跳到按该组筛选的列表（`/?group=<slug>`）
- **AND** 该页只显示这一组的 Book

### Requirement: 管理端 MUST 提供组管理入口与可视化归属

管理端 MUST 有「组」管理页（列表 + 新建/改名/删除/上下移）与 Book 侧的组入口：Book 列表 MUST 显示所属组，Book 表单 MUST 用必选下拉呈现组。

#### Scenario: Book 表单必选组

- **WHEN** 打开新建 Book 表单
- **THEN** 组是必选下拉，默认不选中
- **AND** 提交时未选组会看到字段级错误

#### Scenario: Book 列表可按组筛选

- **WHEN** 在管理端 Book 列表选择某个组
- **THEN** 列表只剩该组的 Book
- **AND** 仍在显示已发布/全部章节数

### Requirement: 写操作成功 MUST 有可见反馈

创建章节、保存章节、新建 Book、保存 Book 成功后 MUST 通过 PRG 重定向回到相应页面并显示结果提示，提示 MUST 说明发生了什么（新建 / 已保存 / 无改动）以及当前版本号（如适用）。提示 MUST NOT 遮挡表单主操作，且 MUST 在用户下一次操作前保持可见。

#### Scenario: 新建章节后有确认

- **WHEN** 管理员提交新建章节表单成功
- **THEN** 页面顶部出现「章节已创建，当前是 v1」之类的提示
- **AND** 表单里是刚保存的内容

#### Scenario: 无改动保存的提示是警告色

- **WHEN** 保存时内容没有变化
- **THEN** 提示明确说明「未生成新版本」
- **AND** 与成功的绿色提示在视觉上可区分

### Requirement: 提交 MUST 防止重复提交

表单提交后 MUST 立即禁用提交按钮并显示「处理中…」，直到页面跳转。带二次确认的表单在用户取消时 MUST NOT 留下被禁用的按钮。

#### Scenario: 双击只提交一次

- **WHEN** 在网络较慢时连续点击两次保存
- **THEN** 第二次点击时按钮已被禁用
- **AND** 只发生一次请求

#### Scenario: 取消确认不锁按钮

- **WHEN** 用户在删除确认弹窗点「取消」
- **THEN** 提交被阻止
- **AND** 按钮仍可点击

### Requirement: 章节保存按钮 MUST 预告版本号

章节编辑页的保存按钮 MUST 显示本次保存将生成的版本号（如「保存为 v3」），让用户在点击前就知道会产生新版本。

#### Scenario: 按钮显示目标版本

- **WHEN** 打开当前版本为 v2 的章节编辑页
- **THEN** 主按钮文案包含 `v3`
- **AND** 页面说明里仍提示保存会生成新版本

### Requirement: 分组与 Book 管理 MUST 使用卡片网格

管理端「分组」页与「Book 列表」MUST 用卡片网格呈现条目，MUST NOT 用表格。卡片 MUST 分三层：头部（图标 + 标题 + 次要标识）、正文（简介/摘要，最多两行截断）、底部（状态信息与操作）。同一行卡片高度 MUST 一致。

#### Scenario: 分组页是卡片而不是表格

- **WHEN** 打开 `/admin/groups`
- **THEN** 每个分组是一张卡片，含图标、标题、slug、Book 数
- **AND** 页面里没有 `table` 元素

#### Scenario: Book 列表是卡片

- **WHEN** 打开 `/admin`
- **THEN** 每本 Book 是一张卡片，含封面或图标、标题、分组、章节数、访问量、更新时间
- **AND** 分页与分组筛选仍然有效

### Requirement: 卡片操作 MUST 横向排布且不撑高卡片

卡片底部的操作（改名/删除、编辑/查看/删除）MUST 横向排布，MUST NOT 竖向堆叠；破坏性操作 MUST 在视觉上可区分并保留二次确认。卡片的次要信息 MUST 用徽章或小字号文本，不得换行撑高整行。

#### Scenario: 操作按钮在一行

- **WHEN** 查看任意分组卡或 Book 卡
- **THEN** 该卡的操作按钮在同一行内
- **AND** 删除按钮仍是危险色且点击后要确认

### Requirement: 列表信息密度 MUST 高于原表格布局

在 1440px 宽视口下，Book 列表 MUST 至少一屏显示 6 张卡片（原表格约 7 行但行高接近 100px）；分组卡片的单卡高度 MUST 明显低于原表格行高（≈100px），且卡内文字 MUST 不因截断而丢失关键信息（标题、分组、数量）。

#### Scenario: 一屏看到更多条目

- **WHEN** 在 1440×900 视口打开 Book 列表且有 12 本书
- **THEN** 首屏可见不少于 6 张卡片
- **AND** 每张卡的标题与分组完整可读
