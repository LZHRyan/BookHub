# Spec Delta

## Purpose

定义 BookHub 的界面表现契约：统一的设计令牌与组件、明暗主题与首屏无闪烁、站点标识、阅读页排版、导航与响应式、管理端信息层次、可访问性基线、空态与错误页，以及动效克制。

## ADDED Requirements

### Requirement: 界面 MUST 由统一的设计令牌派生

所有页面 MUST 使用同一套语义化设计令牌（背景、表面、边框、文字层级、强调色、语义色、圆角、阴影、间距、字体）渲染。组件样式 MUST 只引用令牌而不写死具体色值；修改强调色时 MUST 只改令牌定义即可全站生效。

#### Scenario: 修改强调色后全站一致

- **WHEN** 把强调色令牌从默认值改为另一种颜色
- **THEN** 顶部导航、主按钮、链接、焦点环与选中态同时变为新颜色
- **AND** 不需要修改任何页面模板

#### Scenario: 亮暗两套令牌覆盖同一批组件

- **WHEN** 在亮色与暗色主题下分别打开首页、阅读页与管理端列表
- **THEN** 三个界面的组件形状、间距与层级保持一致
- **AND** 仅颜色取值不同

### Requirement: 主题 MUST 支持跟随系统、亮色、暗色三态

界面 MUST 提供「跟随系统 / 亮色 / 暗色」三态切换，选择结果 MUST 在刷新与后续访问中保持。首屏渲染 MUST NOT 出现亮暗闪烁；当浏览器禁用脚本时，界面 MUST 退化为跟随系统偏好。

#### Scenario: 选择暗色后刷新保持

- **WHEN** 用户切换到暗色主题并刷新页面
- **THEN** 页面在首次绘制时即为暗色，不出现先亮后暗的闪烁
- **AND** 再次访问站点仍为暗色

#### Scenario: 跟随系统时随系统变化

- **WHEN** 用户选择「跟随系统」，随后把操作系统切换到暗色外观
- **THEN** 页面在不手动操作的情况下呈现暗色

#### Scenario: 禁用脚本仍可用

- **WHEN** 浏览器禁用 JavaScript 且系统为暗色外观
- **THEN** 页面以暗色呈现，内容与操作均可正常使用

### Requirement: 站点标识 MUST 在浏览器中可见

站点 MUST 提供图标资源，浏览器标签页 MUST 显示该图标而不再请求到 404。页面标题 MUST 采用「页面名 · 站点名」格式，站点名为空时 MUST 只显示页面名。随主题切换，浏览器地址栏强调色 MUST 与当前主题匹配。

#### Scenario: 标签页有图标

- **WHEN** 打开任意页面并查看浏览器标签页
- **THEN** 标签页显示站点图标
- **AND** 站点不再返回图标资源不存在的错误

#### Scenario: 标题格式统一

- **WHEN** 打开章节阅读页
- **THEN** 浏览器标题为「章节标题 - Book 标题 · 站点名」形式的组合
- **AND** 首页标题只包含站点名

### Requirement: 阅读页 MUST 保证长文可读性

章节正文 MUST 以受限行宽呈现（约 60–80 个字符），行高 MUST 不低于 1.6。标题 MUST 呈现至少 4 级明显的层级差异。代码块与表格在超宽时 MUST 横向滚动且 MUST NOT 撑破页面布局；打印时 MUST 隐藏导航、侧栏与分页控件，正文满宽输出。

#### Scenario: 超宽表格不破坏布局

- **WHEN** 章节正文包含列数很多、宽度超过容器的表格
- **THEN** 表格在自身区域内横向滚动
- **AND** 页面整体不出现横向滚动条

#### Scenario: 打印为可读文档

- **WHEN** 浏览器打印某个章节
- **THEN** 输出中不包含顶部导航、页内目录侧栏与上下篇控件
- **AND** 正文按页面宽度排版

### Requirement: 导航 MUST 标明当前所在位置

顶部导航与侧栏 MUST 用视觉与语义标记当前所在区域（`aria-current`），面包屑 MUST 反映「站点 / Book / 章节」层级。图标按钮 MUST 具备可读名称，不留无语义的纯图标按钮。

#### Scenario: 当前导航被标记

- **WHEN** 管理员停留在「账号管理」页面
- **THEN** 侧栏对应项处于选中态，并带有 `aria-current` 标记
- **AND** 其他项为普通态

#### Scenario: 图标按钮有名称

- **WHEN** 使用屏幕阅读器浏览顶栏的主题切换按钮
- **THEN** 该按钮读出明确的名称（如「切换主题」）
- **AND** 不读出「按钮」而无文字

### Requirement: 布局 MUST 在小屏下可用

视口宽度小于 960px 时，管理端侧栏 MUST 变为可横向滚动的导航条，正文与表格 MUST NOT 产生整页横向滚动。视口宽度小于 720px 时，顶栏搜索框 MUST 收起为可展开的入口。所有可点击控件的触控区域 MUST 不小于 40×40 像素。

#### Scenario: 手机宽度下仍可操作

- **WHEN** 在 390px 宽视口打开管理端 Book 详情
- **THEN** 章节表格在自身容器内横向滚动
- **AND** 导航入口与操作按钮仍可点击且不被裁切

#### Scenario: 搜索框折叠

- **WHEN** 在 390px 宽视口打开首页
- **THEN** 顶栏以图标入口呈现搜索
- **AND** 点击后展开输入框并可提交搜索

### Requirement: 管理端 MUST 区分操作权重与信息层次

管理端列表 MUST 让标题、次要信息与操作区形成清晰的视觉层次；破坏性操作 MUST 与普通操作在视觉上可区分（不同颜色/位置），且 MUST 二次确认。表单 MUST 在字段级展示错误提示与帮助文本。

#### Scenario: 删除操作不与编辑混淆

- **WHEN** 查看 Book 列表的某一行操作区
- **THEN** 删除类操作使用危险语义的视觉样式
- **AND** 点击后要求确认才执行

#### Scenario: 字段错误就近提示

- **WHEN** 提交 Book 表单时标题为空
- **THEN** 标题输入框旁出现错误提示且输入框呈现错误态
- **AND** 其他字段仍保留用户已填内容

### Requirement: 列表与错误 MUST 有明确空态与统一错误页

每个列表页在没有数据时 MUST 展示说明性空态（说明为什么空、下一步做什么），MUST NOT 只留空白。404、403、500 等错误 MUST 使用统一的错误页面，包含状态码、可读说明与返回入口。

#### Scenario: 空 Book 列表

- **WHEN** 站点还没有任何公开 Book
- **THEN** 首页显示「还没有内容」的空态说明
- **AND** 说明中包含管理员如何开始的提示

#### Scenario: 访问不存在页面

- **WHEN** 访问一个不存在的章节地址
- **THEN** 返回统一错误页并显示 404
- **AND** 页面提供返回首页入口

### Requirement: 界面 MUST 满足可访问性基线

所有表单控件 MUST 与可见标签关联。键盘聚焦 MUST 有清晰可见的焦点指示，MUST NOT 依赖颜色单独表达状态。正文文字与背景的对比度 MUST 达到 WCAG AA（≥4.5:1）。当系统要求减少动效时，界面 MUST 关闭过渡与动画。

#### Scenario: 键盘浏览可见焦点

- **WHEN** 使用 Tab 键在登录表单中移动焦点
- **THEN** 当前焦点元素有清晰的轮廓指示
- **AND** 焦点顺序与视觉顺序一致

#### Scenario: 减少动效

- **WHEN** 用户的系统设置为减少动态效果
- **THEN** 页面切换与悬停不再播放入场/位移动画
- **AND** 功能保持完整
