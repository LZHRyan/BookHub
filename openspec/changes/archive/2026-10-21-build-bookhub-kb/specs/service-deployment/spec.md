## Purpose

定义 BookHub 的部署与运维行为契约：单镜像即可运行、配置全部来自环境变量、启动顺序与健康探针语义、数据持久化与备份恢复、升级与子路径反代适配，以及结构化日志输出。

## ADDED Requirements

### Requirement: 镜像 MUST 自包含并以非 root 运行

发布产出的容器镜像 MUST 自带运行所需的全部依赖与静态资源，单个容器 MUST 即可提供完整功能，启动 MUST NOT 依赖外部数据库、缓存、对象存储或外部网络服务。容器内进程 MUST 以非 root 身份运行；运行期需要的可写数据目录 MUST 对该用户可写，其余应用文件 MUST 对该用户只读。

#### Scenario: 只提供一个数据卷即可完整运行

- **WHEN** 部署者以最小配置启动该镜像，仅挂载一个数据卷
- **THEN** 站点、管理端与对外接口都可正常使用
- **AND** 无需额外安装或连接任何外部服务

#### Scenario: 进程以非 root 身份运行

- **WHEN** 容器启动并开始对外服务
- **THEN** 运行服务的进程用户标识不是 root
- **AND** 该进程对数据目录具备读写权限

### Requirement: 配置 MUST 全部来自环境变量

所有运行配置 MUST 通过环境变量提供，且 MUST 随仓库提供一份覆盖全部配置项、默认值与说明的示例清单。缺少必需配置时进程 MUST 启动失败，并以明确的错误信息指出缺失的配置项；MUST NOT 使用不安全的内置默认值静默启动。

#### Scenario: 缺少必需配置时启动失败并指名

- **WHEN** 部署者未提供会话签名密钥等必需配置就启动容器
- **THEN** 容器以非零退出码退出
- **AND** 日志明确指出缺少哪一项配置，且服务未对外监听

#### Scenario: 未提供的可选配置使用默认值

- **WHEN** 部署者只提供必需配置，未设置可选配置项
- **THEN** 服务使用文档中声明的默认值正常启动
- **AND** 启动日志可看出各配置项的实际生效值（敏感值除外）

### Requirement: 启动 MUST 按固定顺序准备数据

容器启动 MUST 依次完成：确认数据目录可写、执行数据库迁移、幂等确保初始管理员存在、再启动对外服务。任一前置步骤失败时 MUST NOT 启动对外服务，并以非零退出码退出且错误信息指出失败阶段。迁移 MUST 幂等，重复启动 MUST NOT 重复施加已应用的变更或破坏既有数据。

#### Scenario: 迁移失败时不对外提供服务

- **WHEN** 启动过程中数据库迁移失败
- **THEN** 容器以非零退出码结束
- **AND** 对外端口上没有可接受请求的服务

#### Scenario: 重复启动保持幂等

- **WHEN** 同一数据卷上的容器被重启多次
- **THEN** 已应用的迁移不重复执行，初始管理员不被重复创建或改密
- **AND** 既有内容与账号保持原样

### Requirement: 健康探针 MUST 区分存活与就绪

`/healthz` MUST 表示进程存活：只要服务能响应请求即返回 200，MUST NOT 因数据存储问题而失败。`/readyz` MUST 表示可对外服务：其中包含对数据存储可读且可写的探测，探测不通过时 MUST 返回非 2xx 状态码。两者 MUST 无需鉴权即可访问。

#### Scenario: 正常运行时两者均通过

- **WHEN** 服务已就绪且数据存储可用
- **THEN** `/healthz` 与 `/readyz` 都返回 2xx
- **AND** 容器编排可据此判定实例可接收流量

#### Scenario: 数据不可写时仅就绪失败

- **WHEN** 数据存储变为只读或不可写
- **THEN** `/readyz` 返回非 2xx
- **AND** `/healthz` 仍返回 2xx，表示进程本身存活

### Requirement: 数据 MUST 持久化在挂载卷上

数据库与运行期产生的全部数据 MUST 位于同一个可挂载的持久目录，MUST NOT 依赖容器可写层的任何状态。容器重启、重建与镜像升级后，内容、版本历史、账号与站点配置 MUST 保持不变。

#### Scenario: 重启后数据不丢失

- **WHEN** 容器被停止并重新启动，仍挂载同一数据卷
- **THEN** 此前创建的 Book、章节正文与历史版本都可原样读取
- **AND** 管理员账号与站点配置保持不变

#### Scenario: 用新容器替换旧容器后数据一致

- **WHEN** 删除旧容器并用新容器挂载同一数据卷启动
- **THEN** 对外接口与页面返回的内容与替换前一致
- **AND** 不出现需要重新初始化或重新创建账号的情况

### Requirement: 备份 MUST 可在运行中产出并可恢复

运维 MUST 能通过随镜像提供的方式产出数据卷的一致备份，备份 MUST 可在服务运行期间执行而不产生损坏或不一致的副本；用该备份在空数据卷上恢复后，MUST 得到内容、历史版本与账号均可读的实例。恢复操作 MUST 在服务停止时执行，并在恢复完成后服务能正常启动。

#### Scenario: 运行中备份得到一致副本

- **WHEN** 服务正常对外提供内容时执行备份
- **THEN** 备份过程不中断的内容读取请求
- **AND** 备份产物包含数据库与内容数据，可用于后续恢复

#### Scenario: 用备份恢复出可用实例

- **WHEN** 在空数据卷上用一份备份执行恢复并启动服务
- **THEN** 站点可正常访问，章节正文与历史版本与备份时刻一致
- **AND** 既有管理员账号可继续登录

### Requirement: 升级 MUST 保持既有数据可用

升级 MUST 通过替换镜像并重启完成，启动过程中自动执行数据迁移，既有数据在新版本下 MUST 可读可写。迁移 MUST 遵循只增不删的原则，使得回退到旧版镜像后旧版本仍能读取该数据；回退流程 MUST 为停止服务、恢复备份、启动旧版镜像。

#### Scenario: 升级后旧数据可读

- **WHEN** 用新版本镜像在同一数据卷上启动服务
- **THEN** 升级前创建的 Book、章节与版本历史都能正常读取
- **AND** 对外接口的既有路径继续按原契约返回

#### Scenario: 回退到旧版本可用

- **WHEN** 运维停止服务、恢复升级前的备份并启动旧版镜像
- **THEN** 服务正常启动并返回备份时刻的内容
- **AND** 不因数据库结构变更而启动失败

### Requirement: 子路径部署 MUST 通过 ROOT_PATH 正确生成链接

当服务部署在反向代理的子路径下时，通过 `ROOT_PATH` 声明该前缀后，页面链接、重定向、静态资源地址与接口文档地址 MUST 都带上该前缀；页面与响应 MUST NOT 生成指向站点根路径的绝对链接。未设置 `ROOT_PATH` 时行为 MUST 与根路径部署一致。

#### Scenario: 子路径下链接与静态资源带前缀

- **WHEN** 服务以 `ROOT_PATH=/kb` 部署并经反向代理访问 `/kb/`
- **THEN** 页面中的导航链接、静态资源地址与重定向都指向 `/kb/...`
- **AND** 静态资源可正常加载，不出现 404

#### Scenario: 未设置前缀时按根路径工作

- **WHEN** 部署未设置 `ROOT_PATH`
- **THEN** 所有链接与静态资源地址指向站点根路径
- **AND** 与子路径部署返回相同的页面内容结构

### Requirement: 日志 MUST 结构化输出到标准流

运行日志 MUST 输出到标准输出或标准错误，MUST NOT 依赖写入容器内文件。每条日志 MUST 为结构化格式，至少包含时间戳、级别与事件名；与请求相关的日志 MUST 包含请求标识与来源 IP。日志 MUST NOT 记录密码、会话令牌或完整鉴权凭据。

#### Scenario: 标准流中可读到结构化日志

- **WHEN** 服务处理若干请求后查看容器标准输出
- **THEN** 每行日志都是可解析的结构化记录，含时间戳、级别、事件名
- **AND** 请求相关日志带请求标识与来源 IP

#### Scenario: 敏感信息不进入日志

- **WHEN** 管理员登录、修改密码或使用 API 凭据发起请求
- **THEN** 日志中不出现明文密码、会话令牌或完整凭据值
- **AND** 仍可通过请求标识定位该次请求的处理过程
