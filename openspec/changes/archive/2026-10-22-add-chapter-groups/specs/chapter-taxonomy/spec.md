# Spec Delta

## Purpose

为 Book 内的章节提供「分卷」这一层组织结构：分卷只有标题与位置，章节可以归属某个分卷，目录与侧边导航据此分组编号，让长篇技术文档有可读的层次。

## ADDED Requirements

### Requirement: 分卷 MUST 只有标题与位置，不含正文

`kind = group` 的记录 MUST 只承载标题、slug 与排序位置，MUST NOT 保存正文、MUST NOT 生成版本、MUST NOT 出现在全文搜索结果中。分卷的可见性跟随其所属 Book，不单独设定状态。

#### Scenario: 分卷不产生正文与版本

- **WHEN** 管理员新建一个分卷
- **THEN** 该记录的正文为空且没有历史版本
- **AND** 用分卷的 slug 请求章节原文接口返回 404

#### Scenario: 分卷不出现在搜索结果

- **WHEN** 用一个分卷的标题作为关键词搜索
- **THEN** 结果里不出现该分卷本身
- **AND** 该分卷下的已发布章节如果正文命中则照常出现

### Requirement: 层级深度 MUST 限制为一层

系统 MUST 只允许「分卷 → 章节」一层归属：分卷 MUST NOT 有父级，章节 MUST NOT 拥有子级。任何试图把分卷挂到分卷下、或给章节设置父级为章节的请求 MUST 被拒绝并返回可辨识错误。

#### Scenario: 分卷不能嵌套

- **WHEN** 新建分卷时指定另一个分卷作为父级
- **THEN** 请求被拒绝并说明只支持一层分卷

#### Scenario: 章节不能作为父级

- **WHEN** 把某章节的归属设置为另一个普通章节
- **THEN** 请求被拒绝并说明父级必须是分卷

### Requirement: 归属变更 MUST 保持排序稳定

章节的归属（`parent`）MUST 可通过管理端与管理 API 修改。变更后该章节 MUST 落在目标父级的末尾，原父级的剩余项 MUST 保持相对顺序不变。

#### Scenario: 章节移入分卷后排在组尾

- **WHEN** 把一个未分卷的章节移入某分卷
- **THEN** 该章节成为该分卷的最后一项
- **AND** 原根层其他条目的相对顺序不变

#### Scenario: 章节移出分卷回到根层

- **WHEN** 把分卷内唯一章节的归属改为「不归入分卷」
- **THEN** 该章节出现在根层，且该分卷变成空分卷（仍然存在）

### Requirement: 删除分卷 MUST 要求先清空

删除仍有子章节的分卷 MUST 被拒绝，并提示先把章节移出或删除。空分卷删除 MUST 为软删除，且可从回收站恢复。

#### Scenario: 有子章节时分卷删不掉

- **WHEN** 管理员删除一个含 3 个章节的分卷
- **THEN** 请求被拒绝并说明还有 3 个章节属于它
- **AND** 分卷与其章节都还在

#### Scenario: 空分卷可删除并恢复

- **WHEN** 删除一个空分卷后从回收站恢复
- **THEN** 分卷回到原来的位置
- **AND** 它仍可接收章节

### Requirement: 目录 MUST 按分卷分组并层级编号

Book 目录 MUST 按「根层顺序」呈现：根层的分卷与其下章节成组显示，未分卷的章节按自身顺序参与根层排列。章节编号 MUST 反映层级（如 `1.`、`1.1`），MUST NOT 因为分组而出现编号跳号。章节页 MUST 在面包屑中标明所属分卷，让读者知道自己读的是哪一卷。

#### Scenario: 分卷与组内章节双层编号

- **WHEN** 一个 Book 根层依次是「分卷 A（含 2 章）」「独立章节」
- **THEN** 目录显示 A 下的两章编号为 `1.1`、`1.2`
- **AND** 独立章节编号为 `2`

#### Scenario: 章节页面包屑带分卷名

- **WHEN** 读者打开归属分卷 A 的某个章节
- **THEN** 面包屑依次显示站点名、Book 标题、分卷 A、章节标题

#### Scenario: 空分卷仍出现在目录

- **WHEN** 某分卷下没有任何已发布章节
- **THEN** 目录仍显示该分卷标题
- **AND** 不显示空的子项列表

#### Scenario: 访问分卷地址回到 Book 页

- **WHEN** 访客直接访问分卷 slug 的章节地址
- **THEN** 系统重定向到该 Book 的目录页而不是返回 500 或空白
