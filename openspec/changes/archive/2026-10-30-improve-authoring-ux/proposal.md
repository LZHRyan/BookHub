# Proposal

## Why

两个具体问题：

1. **保存没有反馈**。新建章节后跳到编辑页，但页面没有任何「已创建 / 当前 v2」的提示；用户不确定是否成功，再点一次保存 → 又生成一个版本。实测：连续点两次「保存并生成新版本」就是 v2、v3，而正文一模一样。
2. **没法分享**。读者看到一篇好文档，只能复制地址栏；管理端想给同事发链接，也没有一键复制入口，IM 里贴链接也没有标题/摘要预览。

## What Changes

- **保存后必有反馈**：创建章节 / 保存章节 / 新建 Book / 编辑 Book 成功后，页面顶部出现一条结果提示，写明「已创建（当前 v1）/ 已保存为 v2 / 内容没有变化，未生成新版本」。
- **没有改动就不产生版本**：标题、正文、slug、格式都没变时，保存 MUST NOT 递增版本号、MUST NOT 写版本记录与审计，只提示「内容没有变化」。这条从根上解决"点两下多两个版本"。
- **防重复提交**：表单提交后按钮立即禁用并显示「处理中…」（有确认弹窗的表单在取消时不锁）。
- **一键复制分享地址**：Book 页与章节页加「复制链接」，复制的是带部署前缀的绝对地址；复制成功按钮显示「已复制」，剪贴板不可用时回退为弹窗让人手动复制。管理端 Book 详情也加同样的入口。
- **分享预览**：Book / 章节页输出 Open Graph 标签（标题、摘要、地址、封面），IM 与社交平台能显示卡片。
- 顺手统一保存按钮文案：编辑章节时按钮显示「保存为 v{{ 当前版本+1 }}」，让"这次点击会做什么"可见。

## Capabilities

### New Capabilities

- `share-links`: 分享地址的形态（绝对 URL、含部署前缀）、一键复制与回退、以及 Open Graph 元数据。

### Modified Capabilities

- `chapter-lifecycle`: 保存时内容无变化 MUST 幂等（不新增版本、不写审计、不触发 Webhook）。
- `web-presentation`: 写操作成功 MUST 有可见反馈；提交后 MUST 防止重复提交；章节保存按钮 MUST 预告将生成的版本号。

## Impact

- **服务层**：`chapters.replace_content()` 增加「无改动直接返回」判定（比较标题/正文/格式/slug）。
- **Web**：`/admin` 下的创建与保存处理器改用 PRG 带 `?notice=<code>`（沿用既有 `?error=` / `?batch=` 约定）；新增模板片段 `admin/_notice.html`。
- **模板**：`book.html`、`chapter.html` 加复制按钮与 OG 标签；`chapter_form.html`、`book_form.html`、`book_detail.html` 接入提示与按钮文案。
- **JS**：`app.js` 增加提交防抖；复制失败回退 `prompt`。
- **测试**：`tests/test_authoring_ux.py`（无改动不生成版本、提示出现、share_url 绝对地址、OG 标签）。
- **文档**：`docs/authoring.md` 补「保存与版本」小节。
- **非目标**：不做短链/二维码、不做分享权限（分享的就是公开地址）、不做撤回编辑的协同提示、不改 API 的保存语义（API 同样幂等：无改动返回原版本号）。
