# Spec Delta

## ADDED Requirements

### Requirement: 写操作成功 MUST 有可见反馈

创建章节、保存章节、新建 Book、保存 Book 成功后 MUST 通过 PRG 重定向回到相应页面并显示结果提示，提示 MUST 说明发生了什么（新建 / 已保存 / 无改动）以及当前版本号（如适用）。提示 MUST NOT 遮挡表单主操作，且 MUST 在用户下一次操作前保持可见。

#### Scenario: 新建章节后有确认

- **WHEN** 管理员提交新建章节表单成功
- **THEN** 页面顶部出现「章节已创建，当前是 v1」之类的提示
- **AND** 表单里是刚保存的内容

#### Scenario: 无改动保存的提示是警告色

- **WHEN** 保存时内容没有变化
- **THEN** 提示明确说明「未生成新版本」
- **AND** 与成功的绿色提示在视觉上可区分

### Requirement: 提交 MUST 防止重复提交

表单提交后 MUST 立即禁用提交按钮并显示「处理中…」，直到页面跳转。带二次确认的表单在用户取消时 MUST NOT 留下被禁用的按钮。

#### Scenario: 双击只提交一次

- **WHEN** 在网络较慢时连续点击两次保存
- **THEN** 第二次点击时按钮已被禁用
- **AND** 只发生一次请求

#### Scenario: 取消确认不锁按钮

- **WHEN** 用户在删除确认弹窗点「取消」
- **THEN** 提交被阻止
- **AND** 按钮仍可点击

### Requirement: 章节保存按钮 MUST 预告版本号

章节编辑页的保存按钮 MUST 显示本次保存将生成的版本号（如「保存为 v3」），让用户在点击前就知道会产生新版本。

#### Scenario: 按钮显示目标版本

- **WHEN** 打开当前版本为 v2 的章节编辑页
- **THEN** 主按钮文案包含 `v3`
- **AND** 页面说明里仍提示保存会生成新版本
