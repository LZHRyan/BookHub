## Why

指南目前直接跳到「用 HTTP API」，但第一次用的人（和 AI）最常问的是更基础的两件事：

- 这个站点的内容是怎么分层的？「知识库 / 分组 / Book / 章 / 节」各管什么，一条资料该放进哪一层？
- 上传的资料有什么格式要求？Markdown 还是 HTML、哪些扩展名、什么编码、多大、多少、图片怎么放？

这两件事写错会导致后续一切返工（书建错格式、文件传不进去、目录乱掉），应该在使用 API 之前讲清楚。

## What Changes

- 指南新增第 2 章「内容怎么组织」（slug `structure`），含两节：
  - 「知识库、分组、Book、章、节」：五层结构图、每层的属性与可见性由谁决定、为什么章没有正文、资料该放哪的决策清单、页面地址与只读 API 的对应、四条易踩规则（必属于分组 / slug 规则 / 排序步长 / 软删除与内置指南）。
  - 「上传资料的格式要求」：整本单一格式与扩展名白名单、编码（UTF-8 / GB18030、NUL 拒绝、换行归一）、数量与体积上限、多文件=多节与文件名到标题的映射、图片附件的白名单与配额、常见拒绝与改法、推荐导入流程。
- 其余章节顺延：用 HTTP API → 第 3 章、接入 MCP → 第 4 章、接入 SKILL → 第 5 章、常见问题 → 第 6 章；文内「见 2.1」等交叉引用同步改成新编号。
- `ensure_guide()` 补章时按固定顺序重排一次：老实例补进新章后目录与新装实例一致，而不是把新章挂在最后；只在确实新增章时重排，用户自己的调整不会被启动流程覆盖。

## Impact

- 代码：`app/services/guide.py`（内容常量、CHAPTERS、`_reorder_to_spec()`）。
- 数据：无需迁移；老实例启动时自动补章并重排。
- 规格：`agent-guide`（内容覆盖范围 + 章节清单 + 升级补章位置）。
- 测试：结构章存在与内容断言、补章后落在第 2 位。
