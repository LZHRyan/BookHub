## MODIFIED Requirements

### Requirement: 通过表单新增章节

系统 SHALL 允许管理员在指定 Book 下通过表单直接录入正文来新增一章，可同时指定章标题、章 slug、发布状态与首批正文。录入的正文 MUST 作为该章的第一节保存（格式默认取 Book 默认格式，也可显式指定），节标题默认取章标题。新增成功后 MUST 产生该节第 1 个历史版本；新章 MUST 排在该 Book 目录末尾。

#### Scenario: 表单新增成功

- **WHEN** 管理员在某 Book 下提交章标题、正文与格式为 `markdown` 的新增请求
- **THEN** 章创建成功并出现在该 Book 的目录末尾
- **AND** 该章下有 1 节，节版本号为 1，内容与提交内容一致

#### Scenario: 未选择状态时默认为草稿

- **WHEN** 管理员新增章时未指定发布状态
- **THEN** 该章以草稿状态保存
- **AND** 访客端目录与章页都看不到它

#### Scenario: 所属 Book 不存在时拒绝新增

- **WHEN** 管理员向一个不存在或已软删除的 Book 新增章
- **THEN** 系统返回 404
- **AND** 不创建章，也不产生版本记录

### Requirement: 通过上传文件新增章节

系统 SHALL 允许管理员上传一个或多个 Markdown / HTML 文件来新增一章：每个文件 MUST 生成该章下的一个节。节标题 MUST 由文件名去掉扩展名后推导（第一章的节标题可被显式填写的章标题覆盖），节的内容格式 MUST 由文件扩展名判定，无法判定的扩展名 MUST 被拒绝并返回可读错误，且整次请求 MUST NOT 落库。

#### Scenario: 文件名推导标题

- **WHEN** 管理员上传文件 `部署指南.md` 且未填写标题
- **THEN** 新章标题为「部署指南」
- **AND** 该节的内容格式标注为 `markdown`

#### Scenario: 显式标题覆盖推导结果

- **WHEN** 管理员上传文件 `draft-v3.html` 并显式填写标题「发布流程」
- **THEN** 新章标题为「发布流程」
- **AND** 该节的内容格式标注为 `html`

#### Scenario: 扩展名无法识别时拒绝

- **WHEN** 管理员上传扩展名不属于 Markdown 或 HTML 的文件
- **THEN** 系统返回 4xx 状态码并提示格式不受支持
- **AND** 不创建章，也不创建任何节

### Requirement: 章节排序调整

系统 SHALL 允许管理员通过上移、下移或直接指定顺序调整章在 Book 目录中的位置。一次排序调整 MUST 以单个原子操作重写整本 Book 的章顺序，调整后 MUST NOT 出现顺序重复或顺序缺号，刷新页面后顺序保持不变。MUST NOT 因为调整某一章而改变其它 Book 的章顺序。

#### Scenario: 上移立即生效

- **WHEN** 管理员把目录里第三位的章上移一位
- **THEN** 该章变为第二位，原第二位章变为第三位
- **AND** 其余章与其它 Book 的顺序不变

#### Scenario: 调整后顺序持久一致

- **WHEN** 管理员完成一次排序调整后重新加载目录页
- **THEN** 章节顺序与调整结果一致

#### Scenario: 调整中失败不改动顺序

- **WHEN** 一次排序请求携带了不属于该 Book 的章标识
- **THEN** 系统返回 4xx 状态码
- **AND** 该 Book 下所有章的顺序保持调整前的状态

### Requirement: 草稿与发布状态流转

章 MUST 处于 `draft` 或 `published` 之一，状态作用在章上：章发布则其下所有节对外可见，章撤回则其下所有节一并不可见。系统 SHALL 支持管理员在两种状态间双向切换；转为 `published` 时 MUST 记录首次发布时间。草稿章 MUST 仅对已登录管理员可见（含按访客视角预览），发布后章页与其下各节 MUST 立即可被访客与外部只读接口读取。

#### Scenario: 发布后立即可被访客读取

- **WHEN** 管理员把草稿章切换为已发布
- **THEN** 该章与其下各节出现在访客端目录中
- **AND** 访客可访问章页与节页，外部只读接口也能取到其内容

#### Scenario: 撤回为草稿后对外不可见

- **WHEN** 管理员把已发布章改回草稿
- **THEN** 该章与其下所有节不再出现在访客端目录与搜索结果中
- **AND** 访客访问章页、节页直链与外部接口请求均返回 404

#### Scenario: 首次发布时间不被覆盖

- **WHEN** 章发布后又被撤回并再次发布
- **THEN** 首次发布时间保持为第一次发布的时间
- **AND** 章按最近更新时间反映在列表排序信息中

#### Scenario: 管理员预览未发布内容

- **WHEN** 已登录管理员以访客视角预览一个草稿章
- **THEN** 预览成功并完整渲染该章下的节
- **AND** 该预览不会使章对匿名访客变为可见

### Requirement: 章节软删除与恢复

章删除 MUST 为软删除：章记录与其下所有节 MUST 保留，各节的历史版本 MUST 完整。删除后该章及其所有节 MUST 立即从访客端目录、章页与节页、搜索结果与外部只读接口中消失（一律表现为 404），管理员 MUST 能在回收站中看到它并恢复；恢复后 MUST 回到删除前的 Book、位置、状态与 slug，节的顺序、内容与版本历史保持不变。

#### Scenario: 删除后对外表现一致

- **WHEN** 管理员删除某已发布章
- **THEN** 访客端目录与搜索结果中不再出现该章及其节
- **AND** 访问章页、节页直链与调用外部只读接口均返回 404

#### Scenario: 回收站可见并可恢复

- **WHEN** 管理员在回收站中恢复该章
- **THEN** 章重新出现在原 Book 的原位置，slug 与删除前一致，其下节一同恢复
- **AND** 发布状态下恢复后访客可立即访问

#### Scenario: 恢复后版本历史完整

- **WHEN** 恢复一个删除前有多个历史版本的章
- **THEN** 该章各节的全部历史版本仍可查看
- **AND** 当前内容与删除前完全一致

#### Scenario: 重复删除幂等

- **WHEN** 管理员对同一章连续发起两次删除
- **THEN** 第二次请求不产生错误状态也不产生额外数据变更
- **AND** 回收站中只出现一条该章记录

### Requirement: 排序 MUST 支持按有序 id 列表整体重排

系统 MUST 提供一次提交完整顺序的重排能力：给定有序章 id 列表，把整本 Book 的章 `sort_order` 重写为 10/20/30…。提交的 id 集合与该 Book 当前未删除章不一致时 MUST 拒绝并返回 4xx，且不改动任何顺序。

#### Scenario: 合法提交重写序号

- **WHEN** 管理员提交某 Book 下 3 个章的新顺序
- **THEN** 该 Book 内顺序与提交一致，序号为 10/20/30
- **AND** 其它 Book 的序号不变

#### Scenario: 集合不一致被拒绝

- **WHEN** 提交的 id 列表包含另一个 Book 的章
- **THEN** 返回 4xx 并说明排序列表不一致
- **AND** 顺序保持不变

### Requirement: 整体替换节内容

系统 SHALL 允许管理员以整份正文替换某一节的内容（不是逐段合并），替换 MUST 为原子操作：该节的正文、格式、标题、当前版本号与内容校验值一并更新，并 MUST 追加一条新的历史版本。替换成功后，该节对外缓存标识 MUST 随之变化；同章其它节与章本身 MUST NOT 受影响。

#### Scenario: 替换产生新版本

- **WHEN** 管理员把某节正文整体替换为新文本
- **THEN** 该节当前版本号递增 1
- **AND** 历史版本列表中出现记录该次替换的新版本，旧版本仍可查看

#### Scenario: 替换后对外缓存标识变化

- **WHEN** 节正文被替换后，调用方带着替换前获取的缓存标识再次请求该节
- **THEN** 系统返回完整的最新内容，而不是"未变更"的响应

#### Scenario: 替换失败不留下半成品

- **WHEN** 一次替换请求因正文超长或格式非法被拒绝
- **THEN** 该节正文、标题与版本号都保持替换前的状态
- **AND** 历史版本列表不新增记录

#### Scenario: 仅改标题也留下可追溯记录

- **WHEN** 管理员只修改节标题并提交替换
- **THEN** 章页的节列表与节页立即显示新标题
- **AND** 历史版本中可查到该次变更

### Requirement: 节历史版本查看

系统 SHALL 为每一节保留可追溯的历史版本列表，每条版本 MUST 至少包含版本号、标题、格式、正文、操作者与时间。版本号 MUST 在该节内单调递增且唯一，列表 MUST 按版本号倒序（最新在前）返回，管理员 MUST 能查看任一历史版本的完整正文。章编辑器与章历史页 MUST 汇总展示「该章各节的版本」。

#### Scenario: 版本列表按时间倒序返回

- **WHEN** 一个经历过 3 次内容写入的节被查看版本列表
- **THEN** 返回 3 条记录，版本号依次为 3、2、1
- **AND** 每条记录都带有操作者与时间

#### Scenario: 查看历史版本正文

- **WHEN** 管理员打开某个历史版本的详情
- **THEN** 显示该版本保存的完整正文与标题
- **AND** 该节当前内容不会被这次查看操作改动

### Requirement: 节版本差异对比

系统 SHALL 允许管理员任选同一节的两个历史版本查看差异，差异结果 MUST 以可辨识的方式标出新增、删除与未变化的部分，并 MUST 标明两侧的版本号。对比操作 MUST 为只读：不产生新版本，也不改动该节当前内容。

#### Scenario: 两个版本显示差异

- **WHEN** 管理员选择版本 2 与版本 5 进行对比
- **THEN** 结果显示两侧版本号，且新增与删除的文本可被区分展示
- **AND** 该节当前内容与版本号保持不变

#### Scenario: 对比相同版本

- **WHEN** 管理员选择同一版本与自己对比
- **THEN** 结果中标记为全部无差异
- **AND** 不返回错误

### Requirement: 节版本回滚

系统 SHALL 允许管理员把某一节回滚到任一历史版本。回滚 MUST 以"把该版本内容作为新内容写入"的方式实现：回滚后 MUST 产生一个新的版本号更大的版本，而不是删除已有版本或把版本号回退；该节当前编号 MUST NOT 减小，章状态与其它节 MUST NOT 改变。

#### Scenario: 回滚产生更新版本号

- **WHEN** 当前版本号为 5 的节被回滚到版本 3
- **THEN** 该节正文与标题变为版本 3 的内容
- **AND** 当前版本号为 6，且版本 6 记录的是该次回滚操作
- **AND** 版本 3、4、5 仍可查看

#### Scenario: 回滚后对外立即可见

- **WHEN** 管理员回滚一个已发布章下的节
- **THEN** 访客刷新节页后看到回滚后的内容
- **AND** 该节在章页节列表中的标题同步更新

#### Scenario: 回滚到不存在的版本被拒绝

- **WHEN** 管理员请求回滚到该节不存在的版本号
- **THEN** 系统返回 404
- **AND** 该节当前内容与版本号保持不变

### Requirement: 节版本保留上限与裁剪

系统 MUST 对每一节保留的历史版本数量设置上限，超出上限时 SHALL 裁剪最旧的版本；裁剪 MUST NOT 删除当前版本，也 MUST NOT 删除被本次操作引用的版本。裁剪行为 MUST 对管理员可预期：查看历史版本列表时看到的是裁剪后的集合，且当前版本始终在列表首位。

#### Scenario: 超限后最旧版本被裁剪

- **WHEN** 某节的历史版本已达上限，管理员又完成一次内容写入
- **THEN** 版本总数不超过上限
- **AND** 最旧的版本从列表中消失，最新版本与当前内容仍可查看

#### Scenario: 当前版本永不被裁剪

- **WHEN** 触发一次版本裁剪
- **THEN** 版本列表中始终包含当前版本
- **AND** 当前版本的内容与该节当前正文一致

### Requirement: 节并发替换冲突提示

系统 SHALL 在替换节内容时接受调用方给出的基准版本标识，并在写入前校验其与该节当前版本是否一致。不一致时系统 MUST 拒绝写入并返回冲突类错误（提示内容已被他人更新），MUST NOT 静默覆盖他人的改动，也不得产生新的版本记录。

#### Scenario: 基准版本过期时拒绝覆盖

- **WHEN** 管理员 A 与 B 同时编辑同一节，B 先保存成功，A 再以打开页面时的旧基准版本提交替换
- **THEN** A 的请求被拒绝并返回冲突错误，提示内容已被更新
- **AND** 该节正文保持为 B 保存的内容，版本号只递增一次

#### Scenario: 基准版本匹配时允许写入

- **WHEN** 调用方以与当前版本一致的基准标识提交替换
- **THEN** 替换成功并产生新版本

#### Scenario: 冲突后重新加载可继续编辑

- **WHEN** 管理员在收到冲突提示后重新加载最新内容并再次提交
- **THEN** 提交成功，版本号在他人保存的基础上继续递增
- **AND** 两个管理员先后保存的内容都能在历史版本中找到

### Requirement: 节内容无变化的保存 MUST 幂等

保存节时若标题、正文、格式与 slug 都没有变化，系统 MUST NOT 递增版本号、MUST NOT 写入新的版本记录、MUST NOT 记录 `section.replace` 审计、MUST NOT 触发 `section.updated` Webhook；页面 MUST 明确提示「内容没有变化，未生成新版本」。

#### Scenario: 连点两次保存只产生一个版本

- **WHEN** 管理员创建节（v1）后在编辑页不做任何修改直接保存两次
- **THEN** 版本号始终是 v1
- **AND** 历史版本里只有 v1 一条
- **AND** 两次保存都提示「内容没有变化」

#### Scenario: 真的改了内容才产生新版本

- **WHEN** 管理员修改正文后保存
- **THEN** 版本号变为 v2，历史版本出现 v2
- **AND** 页面提示「已保存为 v2」

#### Scenario: 只改标题也算改动

- **WHEN** 正文不变但标题改了
- **THEN** 生成新版本（标题是内容的一部分）

## REMOVED Requirements

### Requirement: 章节格式 MUST 与所属 Book 类型一致

**Reason**: 格式已下沉到节：每个节自带 `format`，同一章里可以同时有 Markdown 节与 HTML 节；Book 的 `format` 只是新建节时的默认值，不再限制已存在内容。

**Migration**: 上传或录入内容时按文件扩展名（或显式格式）落库，未指定则继承 Book 默认值；不再有「向 Markdown Book 上传 HTML 被拒绝」的规则。格式与渲染见 `chapter-content`。

### Requirement: 删除分卷 MUST 先清空子章节

**Reason**: 分卷已删除（迁移 `0015_chapter_sections`），不存在「非空分卷不能删」的语义。

**Migration**: 删除章时它的节一起软删除，可在回收站整章恢复；见本能力「章节软删除与恢复」。
