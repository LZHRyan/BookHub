# 内容维护操作手册

面向日常维护文档的同事（`editor` 与 `admin` 角色都能做本文的全部操作）。所有 URL 与表单字段名都取自 `app/web/admin.py` 与 `app/templates/admin/*.html`，可以直接对照页面调试。

---

## 0. 登录

| 操作 | 请求 |
| --- | --- |
| 打开登录页 | `GET /admin/login`（可带 `?next=/admin/books/3`，登录后回跳；只接受以 `/admin` 开头的 `next`） |
| 提交登录 | `POST /admin/login`，表单字段 `username`、`password`、`next` |

- 用户名不区分大小写（`normalize_username` 统一转小写）。
- 同一 IP + 用户名在 `LOGIN_FAIL_WINDOW`（默认 300 秒）内失败 `LOGIN_FAIL_LIMIT`（默认 5）次后返回 **HTTP 429**，页面上提示「登录失败次数过多，请 N 秒后再试」；成功登录立即清零。
- 登录成功后跳到 `/admin`（或 `next`），会话 cookie 默认 8 小时（`SESSION_MAX_AGE`）。
- 退出：`POST /admin/logout`（需要 `csrf_token`）。

## 0.1 术语：访问标识（slug）

后台界面上统一把它叫**「访问标识」**（代码与 API 里仍叫 `slug`），含义是**拼在网址里的那段英文短名**：

| 对象 | 出现在哪 | 示例 | 读者能否看到 |
| --- | --- | --- | --- |
| Book | 读者地址 `/b/<访问标识>` | `/b/handbook` 里的 `handbook` | 能看到（就在地址栏里） |
| 章 | 读者地址 `/b/<Book 的>/<章的>` | `/b/handbook/welcome` 里的 `welcome` | 能看到 |
| 节 | 读者地址 `/b/<Book 的>/<章的>/<节的>` | `/b/handbook/onboarding/env` 里的 `env` | 能看到 |
| Book 分组 | 后台筛选 `/admin?group=<访问标识>`、管理 API | `infra` | **看不到**；读者只看到分组标题 |

规则：同一层级内唯一（章在 Book 内唯一、节在章内唯一），只允许小写字母、数字与连字符；中文标题无法转写时会自动生成 `book-3f7a1c`、`chapter-8c21f0`、`section-3ab1c9` 这类随机串。**改动 Book / 章 / 节的访问标识会让旧链接立即失效**，分组的访问标识改动不影响读者。

## 1. 新建 Book

`GET /admin/books/new` → 填表 → `POST /admin/books/new`

| 字段名 | 控件 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | 文本框 | 是 | 最长 200 字符（超长 400） |
| `group` | 下拉（必选） | 是 | 所属**分组**（首页分区）；下拉里没有「未分组」这一项，留空提交会报错「必须选择分组」。分组在 `/admin/groups` 里新建与排序，见第 6 节 |
| `slug` | 新建页不显示；编辑页文本框 | — | 新建时由标题自动生成，只能落成 `[a-z0-9-]`；编辑页可改成英文/拼音，改后旧链接立即失效 |
| `summary` | 文本域 | 否 | 首页卡片与 Book 页的简介 |
| `icon` | 文本框 + 预置面板 | 否 | 可从内置的 104 个图标（8 个分组）里点选，也可手工粘贴任意字符；留空时前台回退为内置矢量图标 |
| `format` | 下拉 | 是 | **整本文档类型**：`markdown` 或 `html`，没有「混合」选项 |
| `html_view` | 下拉 | 是（仅 HTML 生效） | `document`（默认）：原始文档，章节在新标签页里原样打开；`inline`：站内安全渲染 |
| `visibility` | 下拉 | 是 | `public`（默认，进首页与搜索）或 `unlisted`（直链可读、不进首页与搜索） |
| `csrf_token` | 隐藏域 | 是 | 页面自动填充 |

Book **没有排序权重字段**：首页顺序由系统按访问热度与创建时间自动计算，新建的书自然排到靠前位置，之后随访问量变化（见第 5 节）。

**分组是必选项**：Book 必须属于且只属于一个分组（`books.group_id` 非空），表单里是必选下拉，留空提交会被拦下并提示「必须选择分组」，不会产生"未分组"的书。分组本身决定了首页的分区与分区先后顺序，建组、挪书、删除的前置条件见第 6 节。注意区分：**分组管 Book**，**章管目录行与发布**，**节管正文与版本**。

**新建 Book 不需要填 slug**：表单里没有这个字段，提交后由标题自动生成访问地址（例如标题「运维手册」会得到 `book-1a2b3c`）。想把它改成可读的英文/拼音，去编辑页改 `slug`。

**slug 生成规则**（`app/services/slug.py`）：标题做 NFKD → 只保留 ASCII → 小写 → 非 `[a-z0-9]` 压成 `-`。

- 「研发手册」这种**纯中文标题**转写后为空，会自动回退成 `book-<6 位十六进制>`（例如 `book-c1e1b9`）——这是正常结果，URL 里看到随机串不必奇怪。
- 冲突时依次追加 `-2`、`-3`……，仍然冲突则追加随机后缀。
- 想控制 URL 就手工填 `slug`（建议英文或拼音），例如 `dev-handbook`。

**图标怎么选**：表单里点开「从预置图标中选择（125 个）」，按「书籍与文档 / 技术 / 运维 / 组织 / 其他」分组，点一下即写入输入框并实时预览；右侧「清空」回到无图标。图标是内联 SVG（取自 Lucide），清单在 `app/services/icons.py`，想加图标往对应分组里加一行、把同名 `.svg` 放进 `ICON_PATHS` 即可（测试校验总数 ≥100 且无重复）。

**文档类型是整个 Book 的属性**：

- 新建时必须选一个，站点不提供「同一本书混用 Markdown 与 HTML」。
- 一旦 Book 下已经有章节，类型就**锁定**（编辑页的选择框会禁用）；要换类型只能新建一本 Book，或先把章节全部删掉再改。
- 上传文件时只接受该类型的扩展名（Markdown：`.md/.markdown/.txt`；HTML：`.html/.htm`），传错会被拒绝并提示。

**HTML 阅读方式（`html_view`）**：

- `document`（默认）：原始文档。Book 目录里的章节链接直接在新标签页打开 `/b/{slug}/{chapter}/raw`，上传的 HTML 原样运行——文档自己的 CSS、JS、base64 图片、内置导航全部生效，站点的左栏目录与上下篇在这种情况下不再出现。存量的 HTML Book 已由迁移统一回填成该模式。
- `inline`：站内净化渲染（需手工选择）。`<script>`、内联事件、`<style>`、inline `style`、`data:` 图片都会被移除，只保留结构、文本、`http(s)` 图片与链接；用站点自己的排版和左栏目录。
- 原始文档运行在浏览器沙箱里（CSP `sandbox`，不含 `allow-same-origin`）：脚本会真实执行，但读不到本站登录状态、也拿不到同源接口响应。仍然**只上传可信来源的 HTML**。
- **相对路径资源加载不到**（站点没有附件上传能力）：文档引用的 `./style.css`、`logo.png` 这类相对路径会 404；请把资源内联成 base64 或使用绝对 https URL。`http://` 资源会被浏览器的混合内容策略拦掉。
- Markdown 类型的 Book 忽略该字段，永远走站内渲染。

创建成功后 303 跳到 `GET /admin/books/{book_id}`（Book 详情页），并写一条 `book.create` 审计。

## 2. 新增章节（章 = 容器，节 = 一份文件）

入口：Book 详情页右上「新增章节」→ `GET /admin/books/{book_id}/chapters/new`
提交：`POST /admin/books/{book_id}/chapters/new`（`enctype="multipart/form-data"`）

建章时可以**一次选多个文件**，一个文件生成一节；也可以只粘一段正文（它成为这一章的第一节）。之后在章编辑器里继续「新增节」。

| 字段名 | 控件 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | 文本框 | 是* | 章标题，最长 200。留空时用第一个上传文件的文件名 |
| `slug` | 文本框 | 否 | 章的访问标识，同一 Book 内唯一；留空由标题生成，纯中文标题会得到 `chapter-xxxxxx` |
| `upload` | 多选文件 | 否 | **可多选**：每个文件生成一节，标题取文件名（去扩展名），格式按扩展名 |
| `content` | 文本域 | 否 | 直接粘一段正文（作为第一节，标题取章标题）；与文件同时提交时以文件为准 |
| `status` | 单选卡片 | 否 | `draft`（默认，访客 404）或 `published`（立刻可见），**作用在章上** |
| `encoding` | 单选卡片 | 否 | 留空=自动识别；可强制 `utf-8` 或 `gb18030` |
| `csrf_token` | 隐藏域 | 是 | |

\* 章标题与（`upload` 或 `content`）至少要有其一：

- 既没上传、正文也为空 → 400「请粘贴正文内容或选择要上传的文件」；
- 有上传文件时章标题可留空，用第一个文件名（去扩展名）当标题。

**多文件上传的顺序**就是文件选择顺序，每节的 `sort_order` 步长 10，所以章内编号从 `1.1` 开始依次排。

### 2.1 支持的文件类型与编码

| 扩展名 | 判定格式 |
| --- | --- |
| `.md` `.markdown` `.mdown` `.mkd` `.txt` | Markdown |
| `.html` `.htm` `.xhtml` | HTML（入库前按白名单净化） |
| 其他 | 拒绝：`不支持的文件类型 .docx，仅接受 .md/.markdown/.txt 或 .html/.htm` |

> 页面上的 `accept` 属性只列了 `.md,.markdown,.txt,.html,.htm`，但后端实际还接受 `.mdown`、`.mkd`、`.xhtml`——用「所有文件」手选也不会被拒（这几个扩展名）。
>
> **格式是节级的**：Book 的「文档类型」只是新建节时的默认值，同一章里可以既有 `.md` 也有 `.html`；不再出现「这本是 HTML 书，所以不能传 md」的限制。

编码识别顺序（`app/services/encoding.py:decode_bytes`）：

1. 有 **UTF-8 BOM** → 按 UTF-8 解码；
2. 严格 **UTF-8**；
3. **GB18030** 试探（覆盖 GBK/GB2312 的老文档）；
4. 都失败 → 报错，提示另存为 UTF-8。

另外：含 **NUL 字节**的文件直接判为「疑似二进制」拒绝（否则 GB18030 会把任意二进制"成功"解成乱码）；换行统一归一化为 `\n`（CRLF/CR 都会被处理）。

### 2.2 上限

| 限制 | 默认值 | 配置项 | 超限表现 |
| --- | --- | --- | --- |
| 单文件字节数 | 5 MiB（5242880） | `MAX_UPLOAD_BYTES` | 页面提示「文件超过上限（5 MiB）」（对应错误码 `file_too_large` / 413） |
| 单节正文字符数 | 500000 | `MAX_CONTENT_CHARS` | 页面提示「正文超过上限（500000 字符）」（对应错误码 `content_too_long` / 422） |

> 注意状态码差异：这两个例外在**管理端表单**里会被捕获并渲染成表单错误页（HTTP **400**），只有错误体里的 `code` 保留 `file_too_large` / `content_too_long` 语义。也就是说自动化脚本判断"是文件太大"要看 `code`，不要只看状态码。

两个限制对**上传和粘贴都生效**（字符数限制作用在解码后的单节正文上）。上千页的手册也在 500000 字符内，但**不要把整本手册塞进一节**——按 `##` 一级主题拆成节，便于检索与增量同步。

### 2.3 创建后发生了什么

- 章：`sort_order = 该 Book 当前最大 + 10`（自动排在最后），`status` 取表单值，`published_at` 在首发时写入。
- 每一节：`sort_order = 该章当前最大 + 10`、`current_version_no = 1`，同时写入一条 `section_versions`（备注默认「新建章节」）。
- Markdown 走 CommonMark + 表格/删除线/任务列表/脚注/定义列表，代码块用 Pygments 高亮并生成 `pygments.css` 里的类名。
- HTML 节先净化再加锚点：`script`、事件属性、`javascript:`、`iframe`、`form` 等一律剔除；允许 `http/https/mailto` 链接。**净化结果会落库**，不是展示时临时处理。
- 标题自动生成锚点（保留中文），并抽出 `content_toc` 供左侧「本页目录」使用。
- `word_count` = 中文字符数 + 英文词数，用于目录页展示。
- 审计：一条 `chapter.create`（detail 里带 `sections` 数量）+ 每节一条 `section.create`。

### 2.4 插入图片与附件（媒体库）

技术文档里的架构图、报错截图、PDF 附件不用再传外部图床：节编辑器支持三种入口，产物完全一样。

| 入口 | 操作 |
| --- | --- |
| 粘贴 | 光标放在正文里，直接 `Ctrl+V` 粘贴截图 |
| 拖拽 | 把文件拖到正文区域（出现高亮即已就绪） |
| 点选 | 编辑器下方「点选上传」，可多选 |

上传成功后按光标位置自动插入引用：

- Markdown 节：`![原始文件名](/media/<book-slug>/<hash16>-<文件名>)`
- HTML 节：`<img src="/media/<book-slug>/<hash16>-<文件名>" alt="原始文件名">`
- 非图片附件插入链接（`[文件名](...)` / `<a href="...">`），读者点击按原文件名下载。

**规则**

- 单个文件上限 `MEDIA_MAX_BYTES`（默认 20 MiB）；每个 Book 总量上限 `MEDIA_QUOTA_BYTES`（默认 500 MiB）。
- 类型按「扩展名白名单 + 文件内容嗅探」双重判定，两者不一致直接拒绝（415）；SVG 里出现 `<script>` / `onload=` 也会被拒。
- 相同内容重复上传只占一份空间，返回同一个地址（地址里带内容哈希，浏览器可长期缓存）。
- Book 详情页的「媒体库」列出全部资源：缩略图、字节数、是否被引用、复制地址、删除。
- 删除是**软删除**：已发布节里的图片仍然显示（物理文件保留），但地址不再公开可读；想彻底回收走「清理未引用资源」。

**设置封面**

封面复用媒体库里的图片，不另建一套存储：

1. 打开 Book 详情页 →「媒体库」→ 上传（或选已有）一张图片；
2. 点该图片卡片上的「设为封面」；再点「取消封面」即可撤销；
3. 首页卡片与 Book 页顶部会优先显示封面，没设封面时回退到内置 SVG 图标。

- 只有**本 Book 自己的图片**能当封面（不能借用别的 Book 的图），附件不行。
- 建议尺寸 1200×600 左右、200KB 以内：首页按 148px 高、等比裁切显示（object-fit: cover），过大的图只是徒增加载量。
- 删除正被用作封面的图片时，封面会**自动解除**并回退到图标，不会出现破图。

**维护提示**

- 图片必须放在**本 Book** 的媒体库里；跨 Book 复用目前需要分别上传。
- 改过 Book slug 之后，旧正文里的 `/media/<旧slug>/...` 会失效，媒体库页会把这些地址列为「失效媒体地址」，按提示替换即可。
- 未引用资源清理默认只预览清单，确认后才软删；已删除超过 `MEDIA_PURGE_GRACE_DAYS`（默认 7 天）且仍无引用的资源才会被物理删除。
- HTML Book 的「原始版式」模式（新标签页）带 CSP `sandbox` 且不给 `allow-same-origin`，浏览器不会带 Cookie 请求图片；因此 **unlisted Book 的原始版式页面里图片会加载失败**，换成站内渲染模式或把 Book 设为 public 即可。

## 3. 编辑：章信息与节内容分开

一章由两部分组成，后台也是两个页面：

| 页面 | 地址 | 改什么 |
| --- | --- | --- |
| 章编辑器 | `/admin/books/{book_id}/chapters/{chapter_id}` | 章标题、访问标识、发布状态，以及**节列表**（标题/格式/字数/版本/上移下移/删除/加节） |
| 节编辑器 | `/admin/books/{book_id}/chapters/{chapter_id}/sections/{section_id}` | 单节的标题、slug、格式、正文、上传替换、编码、版本备注 |

章信息提交：`POST /admin/books/{book_id}/chapters/{chapter_id}/info`（字段 `title`、`slug`、`csrf_token`）。改章标题**不产生版本**（章没有版本）。

### 3.1 节内容替换

提交：`POST /admin/books/{book_id}/chapters/{chapter_id}/sections/{section_id}/replace`

| 字段名 | 说明 |
| --- | --- |
| `title` / `slug` / `format` / `content` / `encoding` / `upload` | 同新增；`format` 可在 `markdown` / `html` 之间改 |
| `base_version` | **隐藏域，页面自动填当前版本号**——并发保护靠它 |
| `note` | 版本备注（最长 200），留空存为「替换内容」 |
| `csrf_token` | |

行为要点：

- 每次保存都 **生成新版本**（`current_version_no + 1`），旧内容进入历史版本，随后按 `VERSION_RETENTION`（默认 50）裁剪最旧的版本，**当前版本永不裁剪**。
- `current_version_no` 是**每节各自的**：改 A 节不会让 B 节的版本号变大。
- 只改标题或格式也算一次替换，同样 +1 版本。
- **正文本地留空且没有上传文件时，沿用当前正文**——所以「只想改标题」是安全的，不会清空内容，但仍会 +1 版本。
- 替换会重算 `content_rendered` / `content_toc` / `word_count` / `content_checksum`，并**在同一事务里覆盖检索索引**，所以改完立刻能搜到新内容。
- `slug` 在替换时同样生效：改了它并保存，节 URL 立即换成新 slug（同一章内重名会自动追加 `-2`），旧链接失效。留空表示不改。
- 写一条 `section.replace` 审计（`detail` 里带 `chapter_id` / `from_version` / `to_version` / `note`），并发一条 `section.updated` Webhook。

### 3.2 并发冲突（`base_version`）

`base_version` 与当前版本号不一致时，服务层抛 **409 conflict**「内容已被他人更新，请重新加载后再保存」，并且**不写库**。

- 网页端表现：回到编辑页并显示该提示（页面 HTTP 状态是 400，因为路由把业务异常渲染成了表单错误页）。
- 处理方式：刷新页面拿到最新版本号再重新粘贴/上传，或先到「历史版本」对比一下别人改了什么。
- 不带 `base_version` 时按「写入者胜出」处理（脚本化调用走这个路径），仍有版本记录与审计。

### 3.3 保存与版本：没有改动就不产生新版本

- 保存时只有**标题 / 正文 / 格式 / slug** 真的变了，才会生成新版本；完全没改动时保存是幂等的——版本号不动、历史版本里不会多出一条、也不会写 `section.replace` 审计或触发 `section.updated` Webhook。
- 页面会明确告诉你结果：顶部提示「已保存为 v3」或「内容没有变化，未生成新版本（仍是 v3）」。
- 编辑页的保存按钮直接写着目标版本号（如「保存为 v3」），点之前就能知道这次会不会产生版本。
- 想"只留一个标记版本"（比如只改版本备注）目前不行：备注不参与判定，改内容才会产生新版本。

### 3.4 章内的节：新增、排序、删除

| 操作 | 入口 | 说明 |
| --- | --- | --- |
| 新增节 | 章编辑器右上「新增节」或节列表下方空状态 | `GET/POST /admin/books/{book_id}/chapters/{chapter_id}/sections/new`，也支持**多文件一次生成多节** |
| 上移 / 下移 | 节列表每行的箭头 | 只在该章内移动；位于首/尾时是空操作 |
| 删除节 | 节列表每行的「删除」 | 软删除该节（立即对访客消失），章与其它节不受影响 |
| 恢复节 | `POST .../sections/{id}/restore` | 目前没有界面上入口，需要恢复走 API |

> 不做「拖拽排序节」与「把节移到别的章」：前者没必要（一节一文件的顺序改动不频繁），后者容易把 URL 与版本关系搞乱，需要时请在新章里新建一节再删掉旧的。

## 4. 发布 / 撤回（章级）

入口：Book 详情页每行的「发布」或「撤回」按钮、章编辑器右侧的状态卡，或勾选多行用顶部「批量发布 / 批量撤回」。
请求：`POST /admin/books/{book_id}/chapters/{chapter_id}/status`，表单字段 `status=draft|published`（外加 `csrf_token`）。

- 状态只有 `draft` 与 `published` 两种，**只在章上**；节没有独立状态。
- 章 `draft` → **它下面所有节对访客一律 404**：章页、节页都 404，不出现在 Book 目录、首页、搜索结果与 `/api/v1` 里。
- 章 `published` → 所有节一起可见（不会出现"半章可见"）。
- 首次发布时写入 `published_at`；之后撤回**不会清空** `published_at`（它只表示"第一次发布的时间"）。
- 已发布章出现在 `/api/v1/books/{slug}` 的 `chapters` 数组里（带 `status` 与其 `sections` 列表）。
- 审计动作：`chapter.publish` / `chapter.unpublish`；Webhook：`chapter.published` / `chapter.unpublished`，发布时每个节还会各发一条 `section.published`。
- 想整体检查再统一放行：建议批量导入时全部建成草稿，逐章点开看渲染效果，最后逐个发布。管理员登录状态下可以直接点节页的「编辑」链接核对，访客视角请用无痕窗口。

## 5. 排序

### 5.1 Book 之间的顺序（自动）

Book 顺序**没有人工入口**，由 `app/services/ranking.py` 在每次列表请求时算出：

```text
weight = 100 × ln(1 + 近 7 天访问数) + 25 × ln(1 + 累计访问数) + 60 × 2 ** (-创建天数 / 14)
```

- 权重越大越靠前；权重相同时新建的靠前，再按 id 倒序兜底。
- 访问计数来自访客读某一**节**（`section_view_daily`，按节记；一本书的热度 = 它各节之和），**登录用户的访问不计入**；同一 IP 对同一本书 30 分钟内只计一次，刷新不会刷热度。Book 目录页本身不计热度。
- 想让某本书更靠前：把它分享出去让人读，而不是找设置项——确实没有设置项。
- 例外是**置顶**：Book 详情页右上角「置顶到首页」把这本书钉在最前面（`books.pinned`）。置顶的多本之间仍按上面的权重排序；取消置顶后立刻回到按权重算出的位置。这是唯一的人工干预入口。
- 管理端「Book 详情页」顶部的「热度权重 / 近 7 天访问 / 累计访问」三个徽章就是公式的输入与结果。

### 5.2 章节之间的顺序（手工）

| 操作 | 请求 | 说明 |
| --- | --- | --- |
| 拖拽排序 | `POST /admin/books/{book_id}/chapters/reorder`（JSON：`chapter_ids`） | 行首手柄拖动，松手后按该列表顺序整体重写 10/20/30 |
| 上移 / 下移 | `POST /admin/books/{book_id}/chapters/{chapter_id}/move`，字段 `direction=-1` 或 `1` | 与相邻章交换位置，然后把该 Book 的 `sort_order` 重写为 10/20/30… |

- 拖拽覆盖**整本 Book** 的章列表（分卷已删除，目录只剩一级）。
- 提交的是该 Book 的**完整有序 id 列表**：少一个或多一个都会被拒绝（可能有人同时在改），页面会提示并重载回真实顺序。
- 排序作用域是 Book：章共用一套序号。
- 章排序键是 `(sort_order, created_at, id)`，所以 `sort_order` 相同的章按创建时间排。
- 每做一次调整都会重写序号，这是有意为之：避免「手工插值」把序号磨成 0 或负数。
- 页面上显示的 `10/20/30` 就是库里真实值，不是序号重排后的显示值。

### 5.3 节之间的顺序（章内）

| 操作 | 请求 | 说明 |
| --- | --- | --- |
| 上移 / 下移 | `POST /admin/books/{book_id}/chapters/{chapter_id}/sections/{section_id}/move`，字段 `direction=-1` 或 `1` | 只在该章内与相邻节交换，然后把该章的节序号重写为 10/20/30… |

- 节**不支持拖拽**，也**不能跨章移动**（`sections.move_to_chapter` 显式拒绝）。要把内容搬到另一章，就在新章里新建一节再删掉旧的。
- 目录里显示的 `1.1`、`1.2` 是派生编号（章号 + 章内节序），`sort_order` 变化后编号随之变化。

## 6. 分组：把 Book 归到主题下

分组是 Book 的上一层：`组 → Book → 章 → 节`。一个组就是首页上的一个分区，**每本 Book 必须属于且只属于一个分组**（`books.group_id` 非空），系统里没有「未分组」这种状态。

### 6.1 建组与排序

| 操作 | 请求 |
| --- | --- |
| 分组列表（含每组的 Book 数） | `GET /admin/groups` |
| 新建分组 | `GET/POST /admin/groups/new` |
| 改名 / 改 slug / 简介 / 图标 | `GET/POST /admin/groups/{group_id}/edit` |
| 上移 / 下移 | `POST /admin/groups/{group_id}/move`，表单字段 `direction=-1` 或 `1`（外加 `csrf_token`） |
| 删除 | `POST /admin/groups/{group_id}/delete`（前置条件见 6.3） |

| 字段名 | 控件 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | 文本框 | 是 | 最长 120 字符（超长 400）；首页分区的标题 |
| `slug` | 文本框 | 否 | 留空由标题生成，**站内唯一**（冲突自动追加 `-2`…）；只用于 API 与 `?group=` 筛选，不出现在读者地址栏 |
| `description` | 文本域 | 否 | 分区标题下的说明，留空不显示 |
| `icon` | 文本框 | 否 | 图标名（如 `folder-tree`），显示在分区标题与 Book 页的面包屑里 |
| `csrf_token` | 隐藏域 | 是 | 页面自动填充 |

- 组的顺序就是首页分区的顺序（`book_groups.sort_order`）。上移/下移与**相邻的组**交换位置，然后把全部组的序号整体重写为 10/20/30…，页面上看到的数字就是库里真实值，不是显示序号。
- 新建的组自动排到最后（`sort_order = 当前最大值 + 10`）。
- 组的 slug 与 Book 的 slug 是两套东西：组的 slug **不参与任何读者 URL**，改它不会让读者的收藏失效，但会让还在用旧值的 `?group=` 链接与脚本过滤失效。

### 6.2 把 Book 归到组里

- 新建 Book 时在「分组」下拉里选一个（必选，见第 1 节）；已有的 Book 在编辑页改这个下拉即可换组。
- 换组只改 `books.group_id`：章节、历史版本、媒体库、封面、slug 与访问统计全都跟着 Book 走，不需要重新上传。
- **组内顺序没有手工入口**：仍然按「置顶 + 访问热度 + 创建时间」自动计算（见 5.1）。分组只决定"在哪一区"，不决定"区内第几"；想让某本书在组内靠前，只能置顶或让它被更多人读到。
- 分组以卡片呈现，卡片上的「N 本」点得动，跳过去就是管理端按该组筛选后的 Book 列表（`/admin?group=<slug>`）。

### 6.3 删除分组的前置条件

| 情况 | 结果 |
| --- | --- |
| **默认分组**（slug 固定为 `default`） | 一律拒绝：它由系统创建并随系统存在，是「没有指定分组」时的兜底 |
| 组里还有 Book | 拒绝，提示「分组「X」下还有 N 个 Book（含回收站），先把它们移到别的分组」 |
| 组里没有 Book，但它是最后一个组 | 拒绝，提示「至少要保留一个分组，不能删除最后一个」 |
| 空组，且不是默认分组、也不是最后一个 | 直接删除（物理删除，**不进回收站**） |

- **默认分组不可删，也不能改访问标识**：代码里用 `slug = default` 认它（`book_groups.is_default()`），改了标识就再也找不到这个兜底组。它的标题、简介、图标仍可改（例如改名为「未分组」），所以想复用这个分区只需改名字，不用动标识。
- **回收站里的 Book 也算占用**：Book 是软删除，行还在、`group_id` 还指着这个组，所以"删了但没恢复"的 Book 一样会拦住删除。要腾空一个组，得先把回收站里的那本恢复到别的组（Book 编辑页可以改分组），或者直接改库（属运维范围）。
- 分组没有软删除，删掉就没了；被删的只是空壳，Book 与章节不受影响。
- 删不掉时按提示操作：在 Book 列表按该组筛选（`/admin?group=<slug>`），逐本改到别的分组，再回来删。

### 6.4 迁移之后：整理「默认分组」

`0014_book_groups` 迁移会建一个 slug 为 `default` 的「默认分组」，并把当时库里**所有** Book 归入它，所以升级后首页只有一个分区、内容一个不少。

推荐的整理顺序：

1. 在「分组」页按主题建几个真组（例如「基础设施」「业务系统」「规范制度」），用上移/下移把顺序调好——首页从左到右、从上到下就是这个顺序；
2. 逐本打开 Book 编辑页，把「分组」换成目标组并保存（只改归属，不动内容与 slug）；
3. 「默认分组」空了之后，可以把标题改成「未分组」当兜底分区留着（**它不能删除，标识也不能改**）；不想让它出现在首页就保持空组——空分区不渲染。

- 迁移本身不改任何 Book 的标题、slug、可见性与章节，只是补了一个 `group_id`。
- 几十本以上要批量挪，走管理 API 的 `PATCH /api/v1/admin/books/{ref}`，请求体 `{"group": "infra"}`，见 [ai.md](ai.md)。

### 6.5 三层结构：分组 / 章 / 节

界面上有三个层级，各管一件事，不要混着理解。

| 层级 | 管什么 | 谁决定 | 后台位置 |
| --- | --- | --- | --- |
| Book 分组（`book_groups`） | Book 的归类与首页分区顺序 | 人工（上移/下移） | `/admin/groups` |
| Book（`books`） | 一套文档：概览、可见性、封面、文档类型、访问热度 | 人工建/改；顺序自动（置顶 + 热度 + 创建时间） | `/admin/books/{id}` |
| 章（`chapters`） | 目录里的一行：标题、序号、**发布状态** | 人工（拖拽/上移下移、发布撤回） | `/admin/books/{id}/chapters/{id}` |
| 节（`chapter_sections`） | 一份文件：标题、正文、字数、版本（格式跟随 Book） | 人工（节编辑器、上移下移） | `.../sections/{id}` |

- 只有**章**有发布状态：章发布 → 其下所有节一起可见；章草稿 → 全部 404。
- 只有**节**有正文与版本：章没有正文、没有版本号。
- 「分卷」这一层已经删除（迁移 `0015_chapter_sections`），章直接挂在 Book 下，目录编号回到 `1.` / `1.1`。
- `meta.capabilities` 里对应的是 `book_groups` 与 `chapters` + `sections`。

## 7. 历史版本、对比与回滚（节级）

| 操作 | 请求 |
| --- | --- |
| 本章各节版本概览 | `GET /admin/books/{book_id}/chapters/{chapter_id}/versions` |
| 某一节的版本列表 | `GET /admin/books/{book_id}/chapters/{chapter_id}/sections/{section_id}/versions` |
| 查看某一版原文 | `GET .../sections/{section_id}/versions/{version_no}` |
| 两版对比 | `GET .../sections/{section_id}/diff?a=1&b=3` |
| 回滚到某版 | `POST .../sections/{section_id}/rollback/{version_no}`（需 `csrf_token`，页面会二次确认） |

- 版本列表按 `version_no` 倒序，展示标题、格式、备注、操作者、时间。
- 对比是**行级 unified diff**（`difflib`），单次最多渲染 5000 行，超出会截断并提示。对比里 `a` 是左（旧），`b` 是右（新）。
- **回滚不会改版本号**：它把目标版本的标题、格式、正文取出来，**当作一次新的替换**写进去，于是当前版本变成 `N+1`，备注自动写成「回滚到版本 M」。好处是"回滚"本身也能被回滚。
- 回滚**只作用于一个节**：章的状态（发布 / 草稿）不变，别的节不受影响。
- 回滚**不校验 `base_version`**（服务层传的是 `None`），所以先确认没人正在编辑；有 risk 时先看版本列表。
- 审计里回滚记录为 `section.replace`，靠 `detail.note`（「回滚到版本 M」）区分。
- 裁剪：超过 `VERSION_RETENTION`（默认 50）后最老的版本会被物理删除。**如果你可能要靠版本找回几个月前的内容，用备份，不要指望版本表。**

## 8. 删除与恢复

### 8.0 批量操作

Book 详情页每行左侧有复选框，勾选后顶部出现「已选择 n 个章节」，三个按钮分别执行批量发布 / 撤回 / 删除（作用在**章**上，连带它下面的节）。

| 动作 | 行为 |
| --- | --- |
| 批量发布 / 撤回 | 逐条执行，已删除或不存在的条目记为失败，不影响其它条目 |
| 批量删除 | 需要二次确认；软删除进回收站，可恢复 |

- 结果在页面顶部提示「成功 n 条，失败 m 条」；失败只会出现在并发删除/移动的情况下。
- 每次批量操作对每条写一条与单条相同的审计（`chapter.publish` / `chapter.unpublish` / `chapter.delete`）。

### 8.1 章与节

| 操作 | 请求 | 效果 |
| --- | --- | --- |
| 删除章 | `POST /admin/books/{book_id}/chapters/{chapter_id}/delete` | 软删除章（`deleted_at` 打时间戳），把它**所有节**从检索索引移除；节的行与版本记录都保留 |
| 恢复章 | `POST /admin/books/{book_id}/chapters/{chapter_id}/restore` | 清空 `deleted_at`，把它的节重新写回索引；若 slug 已被别的章占用，**自动改名**（追加 `-2`…） |
| 删除节 | `POST .../sections/{section_id}/delete` | 只软删这一节（访客立刻看不到），章与其它节不受影响 |
| 恢复节 | `POST .../sections/{section_id}/restore` | 清空 `deleted_at` 并重新索引；slug 冲突时自动改名 |

- 章与节的删除都在后台以表单按钮触发，都要 `csrf_token`；删除按钮带二次确认。
- 删除章后访客访问章页与它的每个节页都 404；Book 目录里也不再出现。
- 审计：`chapter.delete`（`detail.sections` 记录当时有几节）、`chapter.restore`、`section.delete`、`section.restore`。
- 删除节目前只在章编辑器的节列表里，回收站只列 Book 与章；要恢复已删除的节走管理 API。

### 8.2 Book

| 操作 | 请求 | 效果 |
| --- | --- | --- |
| 删除 | `POST /admin/books/{book_id}/delete` | 只标记 `books.deleted_at`，**章与节的行一个都不动** |
| 恢复 | `POST /admin/books/{book_id}/restore` | 清空 `deleted_at`；若 slug 被新 Book 占用则自动改名 |

- Book 删除后，它的所有章与节对访客与 `/api/v1` 一律 404（读路径都 `JOIN` 过滤了 `book.deleted_at`）。
- 恢复 = 整本恢复，不需要逐章逐节恢复；恢复时若某个章的 slug 在"删除期间"被别人占了，只有该章会被改名。
- 审计：`book.delete` / `book.restore`。

### 8.3 回收站

`GET /admin/trash` 列出所有已删除的 Book 与章（按删除时间倒序），每行一个「恢复」按钮（`POST .../restore`，需 `csrf_token`）。

- 回收站**没有**"彻底删除"入口——数据只会被备份策略带走，删除只是加个时间戳。
- 想彻底清空历史版本/废弃章节，需要数据库操作，属于运维范围。

## 9. 常见坑（都是真实行为）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 章节 URL 是 `chapter-8c21f0` 这种随机串 | 纯中文标题 slug 化后为空，走回退 | 编辑章时把 `slug` 改成英文或拼音并保存 |
| 节 URL 是 `section-3ab1c9` 这种随机串 | 同上（节标题也是中文） | 编辑节时改 `slug` 并保存 |
| 保存节时版本号 +1 但内容没变 | 只改了标题或格式也算替换 | 想完全不动版本就别改任何字段 |
| 连点两次保存只多一个版本 | 第二次内容与第一次相同 → 幂等返回 | 预期行为 |
| 保存时提示「内容已被他人更新」 | 别人在你打开页面后改了同一节（`base_version` 不匹配） | 刷新再改；先看历史版本 diff |
| 上传 `.docx` 被拒 | 扩展名白名单只认 Markdown/HTML | 先转成 `.md` 或 `.html` |
| 上传后中文变乱码 | 文件可能是 GBK 且被其他编码"猜中" | 编码单选显式选 `GB18030 / GBK` 重传 |
| 上传被拒，提示超过上限 | 超过 5 MiB 或 500000 字符 | 拆成更多节；或调大 `MAX_UPLOAD_BYTES` / `MAX_CONTENT_CHARS`（同时调大 nginx `client_max_body_size`） |
| 一次选了 3 个文件，只生成了一章 | 那是设计如此：多文件生成**一章多节** | 打开章编辑器就能看到三节 |
| 想给某一节单独设草稿 | 节没有独立状态 | 只能是整章发布/撤回；确需拆分时把它挪到单独的章（新建+复制） |
| 发布后首页没变化 | 首页只列 `public` 且 Book 可能是 `unlisted` | 检查 Book 的可见性 |
| 发布后搜索不到 | 搜索只覆盖**已发布章**、Book 为 public 且未删除的节 | 同上；同一事务内已更新索引，无需重建 |
| 排序号跳成 10/20/30 | 上移/下移会整体重写序号 | 预期行为 |
| 首页顺序自己变了 | Book 顺序按访问热度 + 创建时间自动计算 | 预期行为；详情页能看到当前权重与访问数 |
| 刷新首页自己看的那本书热度不涨 | 登录用户的访问不计入，且同一 IP 30 分钟内只计一次 | 用无痕窗口或换设备验证；别把自己刷成热门 |
| 升级后首页只有一个分区 | `0014_book_groups` 把存量 Book 全归入「默认分组」 | 预期行为；按 6.4 建组并逐本挪书 |
| 升级后章和节都空了 | 迁移 `0015_chapter_sections` 改结构时**不搬运存量数据**（章内容模型变了，导入不可靠） | 预期行为：升级前用 `scripts/backup.sh` 留快照，升级后按章/节重新录入；Book 与账号保留 |
